# 제품의 본질에서 배치 결정하기

목표는 레퍼런스와 아이디어를 결합해 사용자가 실제로 쓸 수 있는 좋은 제품을 구현하는 것이다. 아래는 사용자가 지정한 OpenClone Douglas 자료의 고객 문제·가치 중심 관점을 UI 설계에 옮긴 **이 패키지의 적용 방식**이다. 인물을 사칭하거나 그의 말투·투자 조언을 제품에 적용하지 않는다.

## 디자인 전 짧은 정의

기존 요구와 자료에서 다음을 정한다. 정보가 충분하면 질문을 반복하지 않는다. 미확인 고객 가설은 가설로 남긴다.

- 누구인가: 특정 사용자와 지금의 사용 상황.
- 무엇이 어려운가: 사용자가 이해·비교·결정·실행하려는 일과 현재 마찰.
- 무엇이 달라져야 하는가: 이 화면에서 완료할 핵심 행동과 성공 상태.
- 필요한 정보는 무엇인가: 그 결정을 내리는 데 필요한 데이터·조건·가격·신뢰 근거.

‘대시보드를 만들자’에서 멈추지 않는다. ‘판매자가 지연 주문을 찾아 발송 대상을 정한다’처럼 구체적으로 쓴다. 시각적 개성도 이 과제와 브랜드를 더 잘 드러내도록 설계한다.

## 요소를 배치하는 기준

중요한 영역/요소에 `E-ID | 필요한 사용자 판단/행동 | 보여줄 정보 | 위치·크기·강조 이유 | 삭제/뒤로 미뤘을 때 영향 | 검증`을 기록한다. 같은 역할의 반복 요소는 묶는다.

1. 정보 확인 → 비교/선택 → 결과 예상 → 실행의 관계를 정하고 읽기 순서로 옮긴다. 실제 사용 빈도·위험·내용 길이를 근거로 위계를 정한다.
2. 주요 행동은 결정에 필요한 정보와 가까이 둔다. 공간이 비어서 KPI·카드·소개 문장을 추가하지 않는다.
3. 장식·이미지·큰 글자도 브랜드 인식이나 콘텐츠 이해를 돕는 구체 역할이 있으면 사용할 수 있다. 핵심 정보를 가리는 비용과 비교한다.
4. 레퍼런스에서는 해결 원리와 시각 문법을 추출한다. 다른 서비스의 정보 구조를 그대로 가져오기 전에 우리 과제에 맞는지 확인한다.
5. 사용자가 요청한 아이디어는 해결하려는 마찰과 기대 효과를 명시해 더한다. 새로움의 개수를 채우거나 여러 제품의 특징을 무작정 합치지 않는다.

## 레퍼런스와 새 아이디어 결합

`채택한 레퍼런스 원리 | 유지할 시각 규칙 | 새 아이디어 | 해결하려는 마찰 | 예상 비용/충돌 | 확인할 사용자 행동`으로 결정한다. 단순 재현을 요청받았다면 그 범위에 맞춘다.

가상 주문 관리 예: 주 레퍼런스의 촘촘한 행·금액 정렬을 유지한다. 사용자가 지연 주문을 먼저 처리해야 한다면 지연 필터와 선택 주문의 발송 요약을 추가할 수 있다. 이는 KPI 장식이 아니라 대상 확인을 돕는 아이디어다. 실패 기준에서 행별 행동 소음이나 중복 CTA가 잡히면 요약의 역할·범위를 검증하며 배치를 수정한다.

완료 기준은 두 축이다. **제품 기준:** 핵심 행동·상태·콘텐츠가 작동하고 필요한 정보를 찾을 수 있는가. **디자인 기준:** 상세 분석·토큰·의도한 개성이 구현됐고 제외 목록과 실패 기준을 통과했는가. 한 축의 통과로 다른 축을 대체하지 않는다. 작은 범위부터 구현·확인하고 발견한 문제를 수정한다.

## 행동의 적용 범위와 위치

버튼을 놓기 전에 `행동 | 실제 변경 대상 | 범위(화면/섹션/항목/선택 집합) | 소속 영역 | 표시 조건`을 정한다. 헤더 오른쪽이 비어 있다는 이유로 섹션 행동을 올려놓지 않는다. 레퍼런스의 버튼 위치도 원래 적용 대상과 우리 제품의 대상이 같은지 확인한 뒤 채택한다.

- 화면 전체에 적용하는 행동은 화면 도구 영역, 목록 전체의 편집은 목록 제목/도구 영역, 항목 하나의 수정은 해당 항목, 선택 항목의 일괄 행동은 선택 상태의 도구 영역을 우선 검토한다. 위치만으로 대상이 모호하면 라벨과 그룹 구조를 함께 고친다.
- Todo의 목록 편집은 날짜/달력을 포함하는 화면 헤더보다 할 일 목록에 속하도록 배치한다. 임시 ‘예시 목록’ 문구가 사라져도 소속과 발견 가능성을 유지해야 한다. 이는 모든 편집 버튼을 하단으로 내리라는 규칙이 아니다.
- 편집 모드 진입 같은 보조 행동을 주요 생성 CTA와 같은 강조로 만들지 않는다. 필터와도 구별하되 목록 도구로 묶을 수 있다. 빈 목록에서 실행할 대상이 없으면 숨김/비활성 등 적절한 상태를 정하고, 편집 종료·선택 취소는 해당 상태에서 찾을 수 있게 한다.

검수 시 ‘무엇에 적용되는지 누르기 전에 알 수 있는가’를 확인한다. 날짜 변경·필터·선택·빈 상태에서 실제 적용 집합과 시각적으로 암시한 범위가 일치해야 한다. 버튼 이동으로 핵심 행동이 긴 목록 끝에 묻히거나 키보드 순서가 어긋나지 않는지도 확인한다. 기능이 존재한다는 이유만으로 위치가 적합하다고 판정하지 않는다.
