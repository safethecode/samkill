# 모바일 적용 기준

모바일 화면을 만들 때만 읽는다. 모바일 레퍼런스를 데스크톱에 단순 확대하지 않는다.

- 실제 과제에 맞는 읽기/탭 순서를 보존한다. CTA가 화면 아래에 보인다는 사실과 fixed 구현은 별개다.
- 목표 좁은 폭, 긴 한국어, 큰 글자 설정, 키보드가 열린 입력 상태에서 잘림과 행동 접근을 확인한다.
- bottom sheet는 내용 높이·safe area·스크롤 영역·닫기 동작을 명시한다. 정지 화면으로 drag-to-dismiss나 배경 탭 닫기를 확인했다고 하지 않는다.
- 손가락으로 누를 수 있는 영역과 아이콘 자체 크기를 구분한다. hover에 의존하지 않고 focus와 접근 가능한 이름을 유지한다.
- 작은 화면에서 핵심 정보를 감추기 전에 사용자가 비교해야 하는 필드를 정한다. 가격·옵션·오류를 생략해 카드 높이만 줄이지 않는다.
- loading/empty/error에서 레이아웃이 급변하거나 CTA가 의도치 않게 이동하는지 확인한다.
- 모바일 원본에 없는 태블릿/데스크톱 동작은 새 설계 결정으로 기록한다.

- [UI 구성 기준](ui-composition.md)에 따라 읽는 글자는 14 CSS px 이상, 본문/입력은 16px부터 검토한다. 글자를 줄여 모바일 폭을 맞추지 않는다.
- 기본·빈 목록·소수 항목에서 불필요한 스크롤이 없는지 확인한다. 긴 내용과 키보드 상태에서 필요한 스크롤은 막지 않는다.
- 목록과 채팅을 함께 요청받으면 두 과제의 공간 경쟁부터 검토한다. 탭/뷰 분리 시 입력 초안과 목록 상태, 탭 복귀 위치를 보존하고 키보드·결과 확인까지 실행한다.
