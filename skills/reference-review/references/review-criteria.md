# 리뷰 기준과 예시

## 비교 항목

| 순서 | 확인할 것 | 실패 신호 |
|---|---|---|
| 구조/과제 | 핵심 데이터·행동, 탐색·비교·선택 | 주문 표가 대형 카드로 대체되어 비교 작업을 방해 |
| 위계/밀도 | 읽기 순서, 첫 화면 정보량, 필요한 여백 | 필요 없는 hero/KPI가 실제 작업을 아래로 밀어냄 |
| 글자/내용 | 긴 한국어, 가격·날짜·단위, 줄바꿈, 대비 | 말줄임으로 식별 불가, 과제와 무관한 데모 통계 |
| 색/표면 | 브랜드·색상 역할, 반경, 선, 그림자 | 이유 없는 무지개 배지, 카드 안 카드, 장식 glow |
| 행동/상태 | 키보드·터치, 선택/오류/로딩/빈 결과, 복구 | hover-only 행동, 화면 캡처로 API 성공 추정 |
| 반응형/일관성 | 목표 폭/높이, 다른 화면의 공통 토큰, 스크롤 | 레퍼런스에 없는 모바일 동작을 검증된 것으로 주장 |

효과가 없다는 관찰과 효과를 넣지 않겠다는 결정은 다르다. 원본 정지 이미지로 원본 애니메이션 부재를 판정하지 않는다. 실제 구현 렌더가 없으면 색·정렬의 확정 결함을 만들어내지 않는다.

한국어 문구를 검토할 때는 설치된 `ux-copy`의 한국어 기준을 함께 적용한다. 번역투, 같은 말의 반복, 버튼과 바로 다음 행동의 불일치, 숨겨진 비용·조건, 거절에 부담을 주는 표현을 확인한다. 실제 문자열을 전달받았다면 텍스트 자체는 검토할 수 있다. 문자열 문제 확인과 화면 배치·클릭 동작 확인은 별도로 기록한다.

## 가상 리뷰 예시

입력: R1 사용자 관찰은 주문 20행 테이블. D1 계약은 행 기반 비교. 개발자는 빌드 통과와 “KPI 4개, 주문 카드 6개”라는 구현 설명만 전달. 실제 구현 이미지 없음.

총괄: **not-verified**. 레퍼런스 적합성과 행동은 실제 화면으로 확인하지 않았다. 빌드 통과는 전달된 빌드 결과다.

| ID/기준 | 근거 | 차이/영향 | 우선순위·상태 | 다음 작업 | 재검증 |
|---|---|---|---|---|---|
| V1/D1 | 사용자 R1 관찰 + 구현 설명 | 행 비교 구조가 카드로 바뀌었을 가능성. 대량 주문 비교 저해 우려 | P1 suspected | 실제 렌더에서 구조를 확인. 사실이면 주문 목록을 정렬된 표로 수정 | 같은 뷰포트에서 열 비교·정보량·일괄 선택 수행 |
| V2/행동 요구 | 실행 근거 없음 | 선택·실패 복구 결과 미상 | priority-unassessed, not-verified | 관련 행동 실행 | 결과와 근거 경로 기록 |

스크린샷 부재 자체를 제품의 P0 버그로 부르지 않는다. 설명만으로 “배지가 6색이고 반경은 24px”처럼 입력에 없는 결함을 만들지 않는다.

## 수정 권한이 있는 경우

확인된 문제 중 사용자 영향이 큰 순서로 고친다. 정상 브랜드·공통 레이아웃까지 교체하지 않는다. 해당 D/V-ID를 유지하고 수정 파일, 재검증 뷰포트·상태·결과를 적는다. 구현 변경 뒤 이전 스크린샷을 최신 증거로 재사용하지 않는다. 전체 렌더가 어려우면 검증한 부분과 남은 부분을 나눈다.

수정 전후 리뷰 항목을 닫으려면 해당 문제의 실제 재검증 근거가 필요하다. 코드 변경이나 추론만으로 `fixed-and-verified`로 바꾸지 않는다.
