# 요소·프롬프트 계약

필드를 채우기 위한 장문 대신 실제 구현 선택을 제한할 정보를 적는다. unknown은 값과 확인 방법을 함께 기록한다. 기존 E/O/Q 표가 있으면 그 표를 확장한다.

## 입력 묶음

`입력 버전 | 출처 R-ID/파일/관찰 영역 | 원본 크기 | 비교 표시 폭·배율 | 원본 CSS/DPR 확인 여부 | 재현/각색/분석 범위 | 사용자 제약 | 에셋 출처`.

E-ID는 출처와 입력 버전 안에서 식별한다. 다른 화면·라운드의 같은 번호를 동일한 요소로 추정하지 않고, 교정 대상에는 R-ID/버전/E-ID를 함께 붙인다.

화면 트리는 부모 소속을, 관계 표는 부모만으로 알 수 없는 정렬·근접·비율·가림을 표현한다. 요소의 터치 영역과 보이는 도형, 글자의 line box와 잉크 크기를 구별한다.

## 요소 계약

| 항목 | 기록 |
|---|---|
| 식별 | E-ID, 출처 R/O와 영역, 역할, 부모, 형제, 실제 표시 상태 |
| 박스 | 관찰 영역과 단위/근거, 구현 폭·높이/min/max와 chosen 표시, 내용 길이에 따른 변화 |
| 여백/관계 | 사방 시각 거리, 내부/외부 소유권, 정렬 기준, 이웃 gap, 사진/텍스트 등 비율 |
| 내용 | 원문, 확신 없는 글자, 줄 수/줄바꿈/잘림, 짧은·긴 변형 |
| 표현 | 글자 역할·크기·굵기·줄높이, 배경/글자/아이콘/경계 조합, 반경·선/채움 |
| 상태 | 실제 관찰과 미확인 동작, 이번 산출물에서 연결할 행동/정적 표현 범위 |
| 재현 | 공유 계약 참조, 요소 프롬프트, 사용 에셋, 출력 컴포넌트, 조립 슬롯 |
| 비교 | 유지할 관계, 확인할 뷰포트/내용 변형, 원본/렌더 증거와 판정 |

일부가 가려진 요소는 보이는 내용과 보이는 컨테이너 경계를 각각 기록한다. 숨겨진 내용·높이가 unknown이어도 관찰된 상단 경계나 부모 소속까지 삭제하지 않는다. 경계가 원본에 보이지 않으면 새로 만들어 넣지 않는다.

‘작은 사진 카드’ 대신 ‘사진이 장소 박스의 왼쪽·위·아래 경계에 붙고, 선택 상자는 그 박스 밖 왼쪽에서 세로 중심을 맞춘다’처럼 쓴다. 이는 설명 방식의 예시이며 모든 카드의 배치 규칙이 아니다. 문장에 없는 여백·순서를 구현자가 보충해야 한다면 선택값으로 정하거나 미결로 밝힌다.

## 실행용 프롬프트

공유 계약에는 화면 조건, 공통 토큰과 단위 근거, 사용자 제약, 에셋, 구현 범위를 둔다. 각 요소 프롬프트에는 **역할 → 부모/박스 → 자식 순서와 관계 → 실제 내용/변형 → 표현 → 상태 → 확인 조건**을 둔다. 조립 계약에는 요소의 읽기 순서, 그룹 내부/사이 간격, 공통 inset 소유자, 고정/흐름의 확인 상태와 이번 선택을 둔다.

이 묶음을 그대로 구현에 전달한다. 결과 코드를 보고 최초 프롬프트를 소급 작성하지 않는다. 원본을 보지 않는 구현 평가에서도 필요한 사진·서체 등 에셋을 명시적으로 전달할 수 있지만 UI를 포함한 전체 캡처를 레이아웃 에셋으로 전달하지 않는다.

## 교정 기록

`F-ID | 라운드/입력 버전 | 사용자 지적 또는 내부 관찰(구별) | 해당 E/관계 | 원본 기대/실제 결과 | 번역 누락·오독/구현 불이행/미확인 원인 | 수정 프롬프트 버전·변경 구절 | 수정 파일 | 재렌더 증거·판정 | 스킬에 올릴 조건·반례 또는 사례 한정`.

예: ‘사진이 너무 작다’는 지적을 ‘앞으로 모든 사진96px’로 저장하지 않는다. 원본은 사진이 부모 높이를 채우는데 결과는 내부 패딩에 의해 작아졌는지 확인한다. 확인됐다면 ‘사진의 경계 접촉과 부모 패딩 소유권을 명시한다’를 해석 기준으로 보완한다. 원본 자체에 사진 여백이 있으면 경계 접촉을 강제하지 않는 것이 반례다.
