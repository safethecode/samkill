# 관찰 기록 계약

필요한 길이만 작성하되 아래 항목은 빠뜨리지 않는다. 단순 검색은 채팅, 구현 연결은 reference brief에 기록한다. 모르는 값은 unknown으로 표시한다.

## 과제

사용자가 완료할 행동 / 플랫폼·뷰포트 / 브랜드·기존 시스템 / 가정.

## 출처별 기록

| 항목 | 기록 내용 |
|---|---|
| ID와 출처 | R1 등, 실제 반환된 ui_url 또는 사용자 자료 경로, 앱/화면 이름 |
| 확인 범위 | 확인 일시, 화면/영상 프레임, 알면 원본 크기와 수집 시점; 수집 시점 미상은 미상 |
| 확인 상태 | inspected / metadata-only / not-inspected |
| 관찰 사실 | 영역과 읽기 순서, 정렬, 정보량, 표면, 상태; 항목마다 O1 등 부여 |
| 수치 근거 | measured: DOM/픽셀 측정 방법, estimated: 시각 추정, unknown |
| 해석 | 관찰이 사용자 과제에 어떤 역할을 할 수 있는지; 효과는 가설 |
| 확인되지 않은 것 | 스크롤 고정, hover, 다음 화면, API 동작 등 |
| 이 화면에 보이지 않는 것 | 관찰한 범위와 함께 기록. 서비스 전체 부재로 확대 금지 |
| 채택/배제 후보 | 대상 요구, 근거 O-ID, 이유, 충돌하는 브랜드 규칙 |

세부 UI 분석이면 [컴포넌트 상세 분석](component-anatomy.md)의 E-ID 표를 추가한다. 화면 밖 간격뿐 아니라 컴포넌트 내부 여백과 글자·아이콘 조합도 기록한다. 각 값에 근거, 좌표계/단위, 측정·추정·미확인을 붙이고 구현용으로 새로 고른 CSS 값과 섞지 않는다.

## 선택

주 레퍼런스와 선택 이유, 보조 레퍼런스의 역할, 제외 후보와 과제 불일치 이유. 숫자를 채우기 위해 레퍼런스를 섞지 않는다.

## 가상 예시 — 실제 UIbowl 결과가 아님

R1: 사용자 제공 `checkout.png`, inspected, 단일 정지 화면, 원본 크기 미상.
O1: 최종 금액이 결제 버튼 바로 위에 보인다.
해석: 행동 전에 지불액을 확인하는 데 도움이 될 수 있다. 전환율 개선은 미검증이다.
채택 후보: 금액 → 결제 행동의 순서.
배제 후보: 이 과제에서 결제 버튼보다 강한 홍보 배너. 결제 정보 확인을 방해하고 관찰된 위계와 맞지 않는다.
미확인: 버튼의 viewport 고정 여부, 결제 실패 흐름, 정확한 간격.

후속 구현은 이 기록을 근거로 D-ID 적용 결정을 만든다. O1 자체에 구현 파일이나 새로운 값을 덮어쓰지 않는다.
