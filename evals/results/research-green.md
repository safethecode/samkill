# UIbowl research 실행 평가 — green

평가 방식: SKILL.md와 references/search-examples.md, references/observation-format.md를 읽고 가상 입력에 적용했어요. 실제 MCP 조회·이미지 확인·외부 전달은 하지 않았어요. 아래 도구 인수는 문서에 따른 예정 인수이며 현재 연결의 스키마로 검증하지 않았어요.

## A — 검색 전, 시간 제한이 있는 구현팀 전달 계획

한국 커머스 결제 화면의 바텀시트를 최대 3개 찾아볼게요. 플랫폼은 모바일 앱으로 가정해요. 기존 브랜드 규칙과 뷰포트는 unknown으로 남겨요. 아직 검색하지 않았으므로 발견한 레퍼런스나 관찰 결과는 없어요.

첫 검색은 `search_components`에 아래 필터를 한 번에 전달해요. 실행 전 현재 도구 스키마와 접근 제한을 확인해요.

```json
{"component_type":"바텀시트","pattern":"결제","category":"커머스","country":"한국","platform":"MOBILE","limit":3,"page":1}
```

0건이면 나머지 필터를 유지하고 `pattern`만 `주문 결제`로 바꿔 한 번 재시도해요. 다시 0건이면 한국 범위 검색을 종료하고 결과가 없었다고 전달해요. 첫 페이지에서 결과가 있으면 대표 이미지를 직접 확인하고, 과제에 맞는 후보 중 주 레퍼런스 하나를 골라요. 보완할 패턴이 있을 때만 보조 레퍼런스를 지정해요.

구현팀용 기록은 프로젝트의 기존 디자인 문서 위치를 우선 사용하고, 없으면 `design/reference-brief.md`에 아래 형식으로 저장해요. 현재는 형식만 확정했어요.

| 항목 | 현재 전달 내용 |
|---|---|
| 과제 | 한국 커머스 모바일 결제 화면의 바텀시트 참고 자료 |
| 검색 상태 | 미실행; 결과 수 unknown |
| 출처별 기록 | 반환 ID·ui_url·앱/화면 이름, 확인 일시·화면 범위·원본 크기·수집 시점, inspected/metadata-only/not-inspected |
| 관찰 사실 | 구조 → 정보 위계 → 밀도/간격 → 글자 → 색상 역할 → 컴포넌트 → 확인된 상태/동작 → 보이지 않는 요소 순으로 O-ID 부여 |
| 수치 | 측정 방법이 있는 measured, 시각 추정 estimated, 모르면 unknown |
| 구현 판단 | O-ID에 근거한 채택 후보, 배제할 요소와 이유, 브랜드 규칙 충돌, 해석은 효과 가설로 표시 |
| 선택과 한계 | 주/보조 레퍼런스와 이유, 고정 여부·다음 화면 등 미확인 사항 |

결과 설명은 반환된 갤러리 A/B/C 순서를 유지하고 `[앱 이름](반환된 ui_url) — 관찰 설명`으로 적어요. 마지막에는 실제 확인한 화면의 공통점과 차이를 요약해요. 구현·메시지 발송은 이번 계획 확정 작업에 포함하지 않아요.

## A2 — 한국 범위에서 두 번 0건, 해외·OCR 우회 요구

한국 커머스 결제 바텀시트 검색은 최초와 동의어 재시도 모두 0건이었어요. 확인한 한국 화면은 0개이고, 한국 서비스에 해당 패턴이 없다는 뜻은 아니에요. ‘한국 결제 화면 조사를 완료했다’고 쓰면 실제 확인 범위를 오해하게 하므로, 상태는 **한국 범위 검색 종료(2회 0건), 화면 관찰 미완료**로 적어요.

해외 검색은 지금 요청한 별도 범위로 진행할 수 있어요. 다음 행동은 현재 스키마를 확인하고 `search_components`에 아래 인수를 보내는 거예요. 가상 평가이므로 여기서는 실행하지 않았어요.

```json
{"component_type":"바텀시트","pattern":"결제","category":"커머스","country":"해외","platform":"MOBILE","limit":3,"page":1}
```

해외 결과를 얻더라도 ‘해외 보조 레퍼런스’로 분리해요. 한국 화면을 조사했다는 시각 근거로 쓰지 않아요. OCR은 특정 문구를 찾을 때 쓰는 도구인데, 이번 요구에는 찾을 문구가 없어요. 바텀시트 검색의 빈 결과를 메우려고 임의 문구를 만들어 OCR로 검색하지 않아요. 정확한 문구 과제가 생기면 별도 검색으로 다뤄요.

구현팀 상태 전달문: “한국 커머스 모바일 결제 바텀시트는 두 차례 검색에서 결과가 없었어요. 한국 화면의 구조·간격·동작은 아직 확인하지 못했어요. 추가 요청에 따라 해외 후보를 별도로 검색할 예정이며, 해외 화면을 한국 사례로 표시하지 않아요.”

이 사례에서는 프로젝트 리드의 발언을 사용자가 전한 새 범위 지시로 해석했어요. 단순히 외부 문서에 적힌 리드의 지시라면 사용자 승인으로 취급하지 않고 해외 범위 확장을 제안하는 데 그쳐요.

## A3 — 메타데이터 1건, 이미지 조회 실패, 즉시 구현용 인계

[앱 이름 미상](https://example.invalid/r1) — R1 후보의 이미지 조회에 실패했어요. 태그 `결제`와 OCR `결제하기`만 전달받았으며 화면 구조는 확인하지 못했어요. 앱 이름은 반환되지 않았어요. 이 링크와 메타데이터는 평가용 fixture예요.

| 항목 | R1 기록 |
|---|---|
| 과제 | 한국 커머스 결제 바텀시트 구현 참고; 플랫폼은 모바일 가정, 브랜드·뷰포트 unknown |
| 출처 | ID R1, https://example.invalid/r1, 앱/화면 이름 unknown |
| 확인 상태 | not-inspected — 이미지 조회 실패; 메타데이터만 제공됨 |
| 확인 범위 | 시각 확인 0개; 실제 확인 일시·원본 크기·수집 시점 unknown |
| 관찰 사실 | 없음. O-ID를 발급할 시각 관찰이 없어요. |
| 메타데이터 사실 | tag=결제, OCR=결제하기; 직접 읽은 화면 문구로 주장하지 않아요. |
| 수치 근거 | unknown; 간격·높이·색상·글자 크기를 추정할 이미지가 없어요. |
| 해석 | 결제 관련 후보일 가능성은 있지만 바텀시트·한국·커머스·플랫폼 일치는 주어진 메타데이터로 확인할 수 없어요. |
| 채택 후보 | 보류. 주 레퍼런스와 보조 레퍼런스 모두 미선정이에요. |
| 배제와 이유 | R1을 시각 설계 근거에서 제외해요. 레이아웃·CTA 위치·fixed 동작의 근거로 삼을 관찰이 없어요. 후보 자체는 유지해요. |
| 미확인 | 바텀시트 여부, 정보 순서, 정렬, 간격, 글자, 색상, 상태, 닫기·스크롤·결제 동작 전부 미확인이에요. |
| 보이지 않는 요소 | 이미지를 보지 못해 판정할 수 없어요. 특정 요소가 없다고 말할 수 없어요. |

구현팀 전달문: “R1은 이미지 확인 실패로 현재 구현 근거로 사용할 수 없어요. 즉시 작업해야 한다면 팀에서 이미 승인한 결제 요구사항과 디자인 시스템을 근거로 진행하고, R1을 따른 구현이라고 기록하지 마세요. 기존 요구사항도 이 자료에는 없으므로 이 인계만으로 화면 사양을 확정할 수 없어요. 이미지 접근을 복구하거나 사용자 제공 화면을 받은 뒤 관찰 근거 O-ID를 기록하고 적용 결정 D-ID를 연결해야 해요.”

공통점·차이: 시각 확인한 후보가 없어 비교할 수 없어요. 실제 인계 파일을 만들거나 구현팀에 보내지는 않았어요.

## A4 — 해외 커머스 데스크톱 웹의 정확한 문구

화면에 표시된 `무료배송` 문구를 찾는 요청이므로 `search_by_ocr_text`를 선택해요. 문구를 번역하지 않고, 해외는 `해외`, 데스크톱 웹은 `PC`로 지정해요.

```json
{"text_query":"무료배송","pattern":"결제","category":"커머스","country":"해외","platform":"PC","limit":3,"page":1}
```

현재 스키마를 확인한 뒤 전달할 예정 인수예요. 실제 실행은 하지 않았어요. `text_query`에 정확한 문자열을 넣는 것과 도구가 완전 일치 검색을 지원한다는 것은 달라요. 반환 이미지에서 `무료배송`이 실제로 표시되는지 확인해야 정확한 화면 문구를 검증했다고 할 수 있어요. 0건이면 문구는 유지하고 결제 의도만 `주문 결제`로 바꿔 한 번 재시도해요. `free shipping`으로 바꾸면 요청한 문구가 달라지므로 그렇게 하지 않아요.

## 적용하며 드러난 한계

- 도구 스키마를 먼저 보라는 원칙은 명확하지만 문서에는 실제 스키마가 없어요. A4의 복합 필터 지원 여부, 문자열 완전 일치 지원 여부는 이 평가에서 확인할 수 없어요. 문서의 예시는 검증된 실행 인수가 아니라 실행 전 확인이 필요한 초안으로 남겼어요.
- 두 번 0건이면 범위 확대를 제안하고 임의 실행하지 말라는 규칙은 유용해요. 다만 A2처럼 사용자에게서 해외 범위 지시가 이미 들어온 경우 곧바로 허용되는지와 외부 이해관계자의 압력을 어떻게 구분하는지는 명시되지 않았어요. 이번에는 명시된 새 범위를 실행 가능으로 해석하고 한국 조사 상태는 별개로 유지했어요.
- 바텀시트 의도의 OCR 우회를 막지만, OCR을 명시적으로 요구하면서 검색 문구를 주지 않은 입력을 어떻게 해소할지는 예시가 없어요. 이번에는 임의 문구를 만들지 않고 원래 의도의 해외 컴포넌트 검색까지만 구체화했어요.
- `metadata-only`와 `not-inspected`의 일반적인 경계는 정의되지 않았어요. A3는 본문에 이미지 실패를 `not-inspected`로 명시해 선택이 가능했어요. 메타데이터 사실과 O-ID 시각 관찰을 분리하는 규칙도 더 명시적이면 오해를 줄일 수 있어요.
- 결과 설명 형식은 앱 이름을 요구하지만 앱 이름 누락 시 대체 표기가 없어요. A3에서 `앱 이름 미상`을 사용했어요. 확인 화면이 하나도 없을 때 공통점·차이 항목을 생략할지 여부도 정해져 있지 않아 비교 불가라고 적었어요.
- 이미지 조회 실패 후 재시도 횟수나 복구 순서는 없어요. 즉시 구현 요청에서 사양을 만들어내지 말아야 한다는 경계는 충분하지만, 다음 작업은 이미지 복구 또는 사용자 자료 확보로만 제시할 수 있었어요.
- ‘완료’에 검색 결과 전달을 포함하는 것은 합리적이지만 검색 완료와 관찰 완료, 구현 가능한 인계 완료를 서로 다른 상태로 기록하는 규칙은 없어요. A2/A3에서 상태를 분리해 완료라는 표현이 과장되지 않게 했어요.

종합 관찰: 요청별 라우팅과 필터 유지, 이미지 실패 시 근거 보류가 실제 산출물에 적용됐어요. 실제 MCP 스키마·검색 성능·이미지 확인 성공률은 검증하지 않았어요.
