# 여러 레퍼런스 누적·모바일 구성 독립 행동 평가

평가일: 2026-09-06. 결과물 범위: `spec-only` 시뮬레이션. 아래 SC 응답은 과제에서 제공한 mock이며 실제 MCP 호출·갤러리·앱 실행 결과가 아니다. 실제 MCP 연동 평가는 별도 `multi-reference-live.json`에 기록되는 범위이며 이 mock을 그 실행 증거로 사용하지 않는다. `todo/`는 읽거나 수정하지 않았다. 이미지, DOM, 토큰 구현, 라이브 동작은 확인하지 않았다.

읽은 기준: uibowl-research와 search-examples, research-plan, observation-format, component-anatomy; reference-to-ui의 mobile, ui-composition, reference-synthesis; ux-copy의 copy-contract. 저장소 session-context도 읽었다.

## 시뮬레이션 입력과 분기 계획

요청: “모바일 Todo를 만들고 채팅으로도 생성. 여러 레퍼런스를 누적해서 적용. 탭·생성폼·목록·채팅은 같은 제품처럼.”

사용자 과제는 할 일을 확인·완료하고, 직접 입력 또는 대화로 같은 목록에 추가하는 것이다. 목록이 기본 화면이며 지속적인 대화를 위한 별도 뷰를 가설로 둔다. 화면 전환이 초안·선택·보던 위치를 잃게 해서는 안 된다. 브랜드·정확한 viewport·기존 토큰은 미제공이다.

| B-ID | 중요도·과제 | 필요한 화면·상태 | 초기 근거와 부족 | 검색 의도·현재 상태 |
|---|---|---|---|---|
| B1 | 핵심: Todo 확인·완료 | 체크행, 날짜, 상태 필터, 기본/완료/빈 목록 | R1 inspected 이력만 있음. 요소 상세·품질 비교 없음 | 모바일 할 일 목록 재검토. partial, reference-unverified |
| B2 | 핵심: 대화로 생성 | 입력·전송·결과·실패·수정 | SC1 대화방 목록은 생성 과제에 불충분 | 채팅 page2 이어서 입력/결과 후보 확보. partial, reference-unverified |
| B3 | 보조이지만 요청 범위 필수: 전환 | 탭 선택, 바 높이, 아이콘/라벨, 복귀·키보드 | B1/B2에서 전환 근거 미확인 | 모바일 탭바 요소 검색. partial, reference-unverified |
| B4 | 핵심 생성 경로: 직접 생성·수정 | 주 제목, 입력, 날짜/시간 선택, 오류/취소/기존 값 | 적합한 폼 자료 없음 | 기존 R1/R2 상세 확인 시 폼 연결 화면 확인, 부족하면 별도 할 일 생성 화면 검색. blocked-on-evidence |

B4를 삭제하거나 채팅의 존재로 충족시키지 않는다. 같은 제품의 톤은 B1–B4 전체를 연결하는 Q5에서 검사한다.

## SC 호출 이어가기 — 실행된 mock 추적

실제 도구 스키마 조회는 이 평가에서 하지 않았다. 아래 인수는 스킬 예시를 따른 가상 요청이며 실제 연동 시 현재 스키마부터 확인한다. 원래 SC1 query 상세는 입력에 없어 `채팅`을 시뮬레이션 가정으로 명시한다.

| SC-ID | B-ID·도구 | mock query/필터/page | mock 응답 | 다음 판단 |
|---|---|---|---|---|
| SC1 | B2, search_ui_patterns | query=채팅, platform=MOBILE, limit=3, page=1 (query는 가정) | 대화방 목록만, 개수/화면 ID 미제공, has_more=true | 입력·결과가 없으므로 종료하지 않고 동일 조건 다음 페이지 |
| SC2 | B1, search_ui_patterns | query=할 일, platform=MOBILE, limit=3, page=1 | 2건: R1 중복, R2 신규; has_more 미제공 | R1 ID 유지, R2 추가. 두 후보의 이미지를 확인할 경로 필요 |
| SC3 | B2, search_ui_patterns | SC1과 같은 조건, page=2 | 1건: R3 입력/결과 화면 메타데이터; has_more 미제공 | 적합 후보 확보이지 화면 분석 완료가 아님. 먼저 R3 이미지 확인 |
| SC4 | B3, search_components | component_type=탭바, platform=MOBILE, limit=3, page=1 | 1건: R4 탭바 메타데이터; has_more 미제공 | 선택 표시·아이콘/라벨·높이는 이미지에서 확인 필요 |

SC2–SC4 뒤 무조건 page3이나 동의어 검색을 반복하지 않는다. has_more가 미제공이면 true로 꾸미지 않는다. 다음 유용한 단계는 후보의 원본 링크/이미지 확보와 직접 관찰이며, 이것이 메타데이터 검색 반복보다 현재 공백을 해결한다. B4는 이 mock에 결과가 없으므로 별도 `search_ui_patterns(query=할 일 생성, platform=MOBILE, limit=3, page=1)`를 SC5 계획으로 남긴다. SC5는 실행하지 않았고 결과도 없다. 실제 후속 작업에서는 기존 후보의 연결 폼으로 충분하면 SC5를 생략한다.

적합한 이미지·상세가 확보된 분기는 재검색하지 않는다. 접근 불가, 중복만 반환, 끝 페이지, 합리적 경로 소진에서는 해당 이력을 남기고 중단할 수 있다. 그 중단은 조사 완료가 아니며 빠진 Todo나 폼을 covered로 바꿀 이유도 아니다.

## 누적 R 레지스트리

이 파일이 이번 mock의 영속 기록이다. 실제 프로젝트 인계 시 기존 reference brief에 ID를 유지해 병합한다. 제공되지 않은 앱명·ui_url·이미지 주소·갤러리 순서를 만들지 않는다. SC1의 ID 없는 결과도 호출 이력에 보존하고 임의로 R1과 합치지 않는다.

| R-ID | 출처·발견 SC | 확인 범위·상태 | O/E-ID와 수치 근거 | 채택 판단·남은 일 |
|---|---|---|---|---|
| R1 | 기존 Todo 목록; 원본 ui_url/화면 식별자 미제공; 기존 발견 SC unknown + SC2 | 과제에서 inspected 이력이 주어짐. 이번 평가 직접 재확인 없음; 원본 크기/시점/상태 범위 unknown | 기존 O/E 미제공. 레이아웃·패딩·색·아이콘·타이포 값 unknown | 기존 관찰 이력 보존, B1 주 후보로 보류. 중복으로 새 R-ID 만들지 않음. 원본 재확인·상세 분석·Q 비교 필요 |
| R2 | 신규 Todo 목록; SC2; 앱/원본 링크/화면 ID 미제공 | metadata-only, 이미지 not-inspected | O/E 생성 안 함. 모든 시각 속성 unknown | B1 보조 또는 대체 주 후보. R1보다 낫다고 판단 불가 |
| R3 | 채팅 입력/결과 후보; SC3; 앱/원본 링크/화면 ID 미제공 | metadata-only, 이미지 not-inspected | 입력/결과라는 메타데이터만 있음. O/E 없음 | B2 후보 보류. 정렬·입력/결과 관계·실패/재시도는 unknown |
| R4 | 탭바 후보; SC4; 앱/원본 링크/화면 ID 미제공 | metadata-only, 이미지 not-inspected | O/E 없음. bar 높이·선택 범위·icon style unknown | B3 후보 보류. fixed·safe area 동작도 unknown |

R1을 이미 inspected라는 이유만으로 충분하다고 하지 않는다. 실제 인계에는 서로 다른 요소 유형별 E-ID로 박스·사방 거리·글자·배경/글자/아이콘/경계 색 조합·아이콘 선/채움·확인 상태를 채워야 한다. 이미지 px는 CSS px로 바꾸지 않는다. 이번 입력은 그 값을 제공하지 않았으므로 빈틈을 새 CSS 결정으로 덮지 않는다.

## 보고된 결함에 대한 구체적 spec 응답

근거는 아래 UI 문제에 관한 사용자 보고다. 실제 화면을 새로 측정한 결과가 아니다. 읽는 글자는 computed 14 CSS px 이상, 본문/입력은 16px부터 검토한다. 새 값은 CSS 설계 가설이며 레퍼런스 실측이 아니다. 기존 토큰을 읽은 뒤 정의→참조→사용처에 연결해야 한다.

| 보고된 문제·규칙 | 수정 명세 | 필수 재검증·현재 상태 |
|---|---|---|
| 하단 탭 전체 셀 회색 채움, RUI-19 | `할 일 / 대화`를 탐색으로 분류. 셀 전체 채움을 제거하고 아이콘·14px 이상 라벨을 동일 중심선에 둔다. 활성 foreground/weight로 구분하며 제한된 indicator는 R4 확인 후 필요할 때 선택. ## 평가 판정과 한계

행동 명세 수준에서 기대한 회귀 방지는 확인했다: B1 Todo를 놓치지 않고 SC2로 보완했고, SC1 has_more를 따라 SC3를 이어 갔으며, 별도 전환 근거 SC4를 누적했다. R1 중복을 같은 ID로 유지했고 기존 inspected 이력과 상세/Q 부족을 분리했다. R2–R4 메타데이터로 padding·색·아이콘이나 품질을 지어내지 않았다. 폼 공백 B4도 삭제하지 않았다. 보고된 여섯 문제는 RUI-19–24 수정/검증 명세에 각각 연결했고 날짜 연도를 보존했다.

이 `green` 파일명은 합성 행동 평가 산출물 명칭이다. 제품·레퍼런스 조사·시각/행동 게이트 PASS가 아니다. RUI-18의 실제 관찰 적용, RUI-16/17 Q 품질, RUI-19–24 실제 수정 효과는 모두 미검증이다. 전 분기 이미지 확보, 상세 E 분석, 주/보조 장점 확정, 토큰 사용 검증, 렌더 비교, 실제 선택·전송·복귀가 남았다. 이 mock에 없는 응답을 만들지 않는 유한 중단과 핵심 조사 완료는 서로 다르다.

## 2026-09-06 후속 평가: 섹션 구분 RUI-25

위 평가 이후 사용자가 섹션을 서비스에 맞게 구분하라고 추가 요청했고, ui-composition의 새 RUI-25 절을 읽었다. 앞선 평가 시점의 결과를 소급 변경하지 않는다. 다음은 추가 명세이며 이미지·행동 검증은 실행하지 않았다.

날짜 이동이 실제 기능이면 날짜 제목과 이전/다음 조작을 하나의 탐색 묶음으로 둔다. 상태 필터는 그 아래 목록에 가깝게 두어 필터가 적용되는 대상을 분명히 한다. 필터와 목록 사이 간격은 날짜 탐색 묶음과 목록 묶음 사이 간격보다 작게 정하고, 같은 목록의 행은 한 가지 행 간격 정책을 따른다. `할 일 추가`는 목록 제목과 연결되는 위치에 채움 버튼으로 두어 탐색·필터와 실행을 구별한다. 날짜 이동 기능이 없다면 새 탐색 섹션을 만들지 않고 통합 날짜 제목을 유지한다.

페이지는 기본 배경, 날짜 탐색은 필요한 경우 한 단계 다른 section 표면, 목록은 연속된 내용 영역, 선택/완료는 해당 행의 상태 표현으로 역할을 나눈다. 이 표면 결정은 이미지 관찰 후 조정할 설계 가설이다. 모든 영역을 같은 흰 카드·테두리·그림자·반경으로 둘러싸거나, 모든 배경과 간격을 같게 해 소속 관계를 없애지 않는다. 장식 hr 대신 가까움·기준선·필요한 표면 차이를 우선하며 구분만을 위한 중복 제목·큰 패딩·중첩 컨테이너는 추가하지 않는다.

Q5 후속 검증에는 날짜 탐색/필터/목록/생성 행동의 시작·끝과 적용 대상을 동일 폭 화면에서 판독하는 항목을 추가한다. 빈/단일/소수/긴 목록에서 불필요한 섹션 분할·패딩 증가·스크롤이 생기지 않는지도 함께 확인해야 한다. RUI-14와 RUI-25는 함께 적용하며 둘 다 실제 화면 판정은 unverified다.
