# samkill-ui 도입 평가 — 2026-09-22

## 범위와 도입 전

사용자는 여러 스킬 이름을 매번 호출하는 부담을 줄이기 위해 `$samkill-ui` 단일 진입점을 요청했다. 작성 전 `test -f skills/samkill-ui/SKILL.md`는 exit 1이었다. 독립 평가 router_baseline도 기존 7개 스킬과 README에서 이름을 찾지 못했다. 기존 스킬을 의미로 연결하는 것은 가능했으므로 기존 UI 판단의 실패로 확대하지 않는다.

## 도입 후 독립 적용

router_check는 새 진입점과 종속 SKILL.md 7개를 읽고 아래 합성 요청 6개를 적용했다. 평가를 위한 전체 읽기이며 실제 모든 사용자 요청에 전체 로딩을 요구하는 것은 아니다.

| 요청 | 확인한 연결·범위 |
|---|---|
| 충분한 분석·DESIGN.md가 있는 한국어 가입 UI 구현 | reference-to-ui 중심, 기존 분해 재사용, onboarding-flow·ux-copy, reference-review. 재검색 불필요. |
| 레퍼런스 검색만 | uibowl-research, 조사·결과 전달. 구현 추가 없음. |
| 결제 오류 문구만 | ux-copy, 제품 사실·조건 보존. 화면·결제 API 변경 없음. |
| DESIGN.md 없는 읽기 전용 리뷰 | reference-review, 문서 누락 보고. 파일 생성 없음. |
| 온보딩 명세만 | onboarding-flow, 필요한 문구/설계 기준, spec-only. 구현·시각 PASS 아님. |
| UIbowl 인증 실패·제공 이미지가 있는 UI 구현 | 실패 표시, 제공 이미지 분해와 독립 구현·검증 진행. 검색 성공 주장 없음. |

발견과 수정: reference-review의 ledger 누적 지시가 읽기 전용 범위와 충돌할 여지를 지적했다. 통합 진입점에 리뷰·게이트·ledger를 대상 파일에 쓰지 않고 채팅으로 전달하며 실제 판독과 기록 미생성을 구별하도록 명시했다.

## 검증과 한계

스킬 quick_validate, UI 메타데이터 YAML, Markdown 로컬 링크 경로, 공백 검사와 개인 연결을 검증한다. 기존 catalog·판독기·제품 코드는 바꾸지 않아 판독기 단위 테스트나 제품 렌더를 이번 검증으로 실행하지 않는다. 독립 합성 적용은 각 1회이며 전체 제품 실행·장기 재현성·앱 자동완성 반영을 입증하지 않는다. 개인 경로의 SKILL.md 접근 확인과 현재 실행 중 앱의 스킬 목록 갱신은 구별한다.


최종 확인: 독립 평가자는 최신 읽기 전용 문단을 다시 읽고 samkill-ui 경유 시 기록 쓰기 우려가 해결됐다고 확인했다. 기존 uibowl-research의 복합 조사 종료 문구가 검색 전용에서도 D/Q 적용을 요구하는 것으로 읽힐 수 있다는 보완 후보는 남긴다. 이번 단순 검색 사례의 차단 요인은 아니며 통합 진입점은 검색 전용 범위를 명시적으로 보존한다. 종속 스킬 원문은 이번에 변경하지 않았다.

실행 결과: quick_validate 통과, 변경 관련 Markdown 6개 파일의 로컬 링크 경로 155개 존재 확인, 공백·메타데이터 YAML·개인 연결·설치 경로에서 형제 스킬 링크 7개 접근 확인, git diff --check 통과. 링크 앵커와 앱 UI 자동완성은 이 검사에 포함하지 않았다.
