# 디맨드로 수행한 두번째 재현 실험

작업일: 2026-09-10 Asia/Seoul. 사용자는 첫 셀레트립 결과를 “정확하게 구현했네”라고 평가하고, 디맨드 서비스로 다른 레퍼런스 실험을 요청했다. 첫 사례의 긍정 평가는 다른 서비스의 정확도 보장이 아니다.

## 자료와 실제 실행

UIbowl에서 디맨드 앱으로1회 조회했다. 소개/멘토검색/통합검색의 대표 이미지를 확인하고 멘토검색을 선택했다. 실제 원본1170×2532를 다운로드해 상태바와 키보드 사이의 앱 영역을 비교했다. 대표 이미지의 표시 크기를 원본 크기로 잘못 사용하지 않도록 파일 크기와 크롭 좌표를 확인했다. 서명URL은 저장하지 않았다.

[P1](../../design/reference-language/round-02/prompt-v1.md)을 먼저 고정하고, 새 구현 담당에게 원본을 보여주지 않은 채 아바타2개와 공식SVG만 제공했다. E1–E5 독립 표본과 조립을 HTML/CSS로 생성했다. 부모와 별도 리뷰 담당만 원본을 보고, 교정은 텍스트 프롬프트 P2/P3으로 전달했다. 구현 담당은 후속 교정에서도 원본을 보지 않았다고 보고했다.

새 공통 catalog 규칙이나 통과 기준을 추가·완화하지 않았다. reference-decompose의 요소 계약에 **고정 박스와 자식 치수 합 검산**, **독립 표본과 조립의 실제 가용 폭 대조**를 보완했다. 좁은 화면의 자연스러운 높이 증가, 사용자가 명시한 서로 다른 폭 비교는 반례로 보존했다. 첫 입력·소스·렌더 및 역사 게이트는 [실험 기록](../../design/reference-language/round-02/review.md)에 연결한다.

## 독립 담당의 후속 행동 시뮬레이션

최신 요소 계약을 읽은 별도 담당에게 이 실험과 다른 숫자의 입력2개 및 반례를 주었다. 현재 디맨드 결과와 원본은 전달하지 않았다.

- 부모52px, 제목24/간격8/배지줄20+상하4씩: 합계60px을 식별하고 min-height52/자연높이60을 선택했다. 좁은 폭 두줄에는84px로 늘어나게 했다. 원본 관계가 부모52고정인지 데이터가 부족함을 명시했다. 실제 디맨드의 gap2px 처방을 외우지 않았다.
- viewport400, 조립inset20, 독립설명padding24: 설명과 표본을 형제로 분리해 두 컴포넌트 실제 폭360을 유지했다. viewport 수치만 같다고 일치 판정하지 않았다.
- 사용자가 독립 컴포넌트280px를 명시한 반례: 강제360px로 고치지 않고 서로 다른 폭 비교로 표시했다.280이 viewport인지 실제 컴포넌트폭인지의 해석을 명시했다.

이는3개 상황의 행동 시뮬레이션이며 실제 렌더나 통계적 정확도 실험은 아니다. 실제 디맨드 렌더 검증과 구별한다.

## 검증과 한계

코드/시각/입력/좁은 폭/키보드와 전체 활성 규칙 판독은 [게이트 리뷰](../../design/reference-language/round-02/gate-review.md)에 기록한다. 비교 보드는 별도 도구이며 실제 이미지·프롬프트 펼침·링크·반응형 검사를 수행한다. 원본 CSS 서체/DPR, 실제 멘토 검색·찜API·키보드 동작은 미확인이다. 이번 디맨드 결과에 대한 사용자 품질 평가는 아직 없다.

최종 정적 표본 게이트는 활성75+프로젝트3=78개에서PASS,errors/failures0이다.36개통과/22개출처재현범위의예외/20개미적용으로원래checks를유지했다. 이판정은정적표본범위의사람판독·증거무결성이며원본픽셀동일이나사용자승인을뜻하지않는다. 검증용JS의기존anti-slop/tsc,새스킬형식,문서링크와diff공백검사를확인했다. 비교보드1100/390/320에서넘침·작은글자·이미지·프롬프트펼침·로컬링크를확인했다.
