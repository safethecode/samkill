# 핵심 화면 비교 단계 — 스킬 평가

평가 실행일: 2026-09-10 (Asia/Seoul). 사용자가 요청한 Git 작성일·커미터 날짜는 2026-09-09이며 평가 실행일과 구별한다. 대상은 [회귀 AB](../cases.md#ab-출처-나열-뒤-관성적인-화면으로-대체한-경우)와 reference-to-ui/reference-review/uibowl-research의 행동 지침이다.

## 실제 실패와 변경 전 확인

기존 스킬에는 이미 원본과 나란히 비교하고 핵심 퇴보를 수정하라는 기준이 있었다. 하지만 이번 대화의 반려동물 코스 시안에서는 출처를 나열한 뒤 큰 사진·연녹색 박스·둥근 버튼을 반복한 이미지로 대체했다. 사용자가 “디자인 AI 같은데? 레퍼런스 하나도 반영 안 된 거 같음”이라고 지적했다. 이는 실제 대화에서 관찰된 실행 실패이며, 스킬에 관련 규칙이 전혀 없었다는 뜻은 아니다.

수정 전 네 문서를 별도 경로에 복사하고 독립 평가 에이전트 `skill_baseline`에 형식 미지정, 밀도 퇴보, API 제한, 이미지 전용, 명세 전용의 다섯 상황을 전달했다. 기준 파일은 수정 전 HEAD `4f7f96a`의 reference-to-ui/SKILL.md, reference-synthesis.md, reference-review/SKILL.md, uibowl-research/SKILL.md와 같았다.

이 평가 응답은 다섯 상황에서 타당한 행동을 선택했다. 실패를 재현했다고 기록하지 않는다. 다만 “형식 미지정 요청의 기본 산출물을 명시한 조항은 없습니다”, “단계별 첫 화면 비교 의무는 찾지 못했습니다”라고 보고했다. 실제 실행 실패를 보존하고 이 두 선택을 명시해, 원칙을 알고도 마지막 검수로 미루는 여지를 줄였다.

## 변경 내용

- 형식 미지정 UI 디자인의 기본 산출물을 수정·렌더 가능한 화면으로 명시했다. 이미지 전용·명세 전용·읽기 전용 요청은 보존한다.
- 핵심 화면의 첫 렌더 → 원본과 같은 표시 폭 비교 → 핵심 퇴보 수정·재검증 → 의존 화면 확장의 순서를 추가했다. 마지막 전체 검수를 대체하지 않는다.
- 조사 인계는 화면별 주 출처/원본 영역/유지할 특징/변경 범위/첫 비교 대상으로 구체화했다.
- 실제 API 제한과 실행 가능한 로컬 검사를 구별하고, 확인한 실패나 미실행 검사를 일괄 unknown으로 바꿔 종료하지 않도록 했다.
- 기존 RUI-16/17 등의 실행 절차를 보강했다. 공통 catalog의 ID·임계값·검사 종류, 판독기 코드·스키마는 바꾸지 않았다.

## 수정 후 독립 행동 평가

별도 에이전트 `skill_updated_eval`이 수정 문서 다섯 개를 읽고 아래 상황의 구체적인 다음 행동과 산출물을 답했다. 파일 편집·UI 생성·렌더를 수행하지 않는 행동 시뮬레이션이다.

| 상황 | 실제 응답 요지 | 판정 |
|---|---|---|
| A 형식 미지정 3화면 | 편집·렌더 가능한 핵심 화면을 먼저 제작·비교하고 퇴보 수정 후 의존 화면과 전체 검수로 진행 | 기대 행동 충족 |
| B 조밀한 일정이 큰 카드로 퇴보 | Q-ID regressed 기록, 행 구조/간격 수정·재비교 후 확장. 카드를 무조건 금지하지 않음 | 기대 행동 충족 |
| C AI API 미연결 | API 의존 행동만 미검증, 로컬 렌더·토큰·문구·정렬 검사와 확인된 실패 수정 계속 | 기대 행동 충족 |
| D 이미지 시안만 | 이미지 형식에서 핵심 시각 비교 후 확장, 코드/CSS/실제 행동 검증을 강요하거나 주장하지 않음 | 기대 행동 충족 |
| E 명세/읽기 전용 | 유지할 특징·토큰 명세·비교 계획 또는 조사 인계까지만 전달 | 기대 행동 충족 |
| F 원본 접근 불가·검색 소진 | 근거 한계를 남기고 요청 범위 내 독립 작업, 소진된 조회 반복/관찰 날조 없음 | 기대 행동 충족 |
| G 새로운 커머스 앱 | 상품/옵션/구매 과제의 실제 원본을 기준으로 선택, 지도/파란색/왼쪽 사진의 일괄 적용 없음 | 기대 행동 충족 |

추가 사용자 승인 단계를 만들지 않는다는 점과 일반적인 레이아웃을 강제하지 않는다는 점도 확인했다. 에이전트는 Q-ID/V-ID/게이트 상태 명칭을 혼동할 수 있다는 경미한 우려를 보고했다. reference-review에 서로 다른 판정 층임을 명시했고, 같은 평가 에이전트가 해당 보완과 기존 A–G 분기의 정합성을 재확인했다.

## 검증 범위와 한계

수정 스킬 3개의 quick_validate 형식 검사를 실행했고 모두 통과했다. 커밋 대상 10개 Markdown 파일의 로컬 링크·앵커 81개, 수정 스킬/참조의 중복 제목, 범위/용어 일관성과 staged diff 공백을 확인했다. 이 결과는 행동 지침의 형식·분기 평가이며 새로운 제품 UI의 품질 향상이나 모든 향후 실행의 준수를 증명하지 않는다.

실제 실패 이후의 제품 재설계에는 별도의 미검증이 남아 있다. 이번 스킬 변경에서 그 제품의 시각/상호작용 게이트를 재실행하거나 PASS로 바꾸지 않았다. 판독기 동작을 바꾸지 않았으므로 design_gate.py의 unittest 실행 결과를 이번 변경의 검증으로 주장하지 않는다.
