# P5 반복 묶음·상태 치수 계약 후속 진단

2026-09-10. 사용자 교정: 매장 구분을 교대표면으로 보강, R3식 입장조건 태그와 의미에 맞는 아이콘, 셀렉트 표현 커스텀, 날짜의 마감 문구가 자신과 형제 높이를 키우는 문제를 문구 제거와 disabled 동일 치수로 수정. 관리 원본의 반복 묶음 계약과 상태 필드, 상태별 치수 안정성 절을 읽고 좁은 적용 진단을 수행했다.

## 방법과 한계

이미 이전 결과/사용자 교정을 아는 동일 평가 담당의 후속 진단이다. 자식 생성·독립 컨텍스트 평가를 하지 않았고 5회 반복 효과/범용성 PASS를 주장하지 않는다. 실제 baseline은 기존 사용자 FAIL과 [P4 날짜 캡처](../../design/reference-language/round-04/evidence/p4-before-row-surfaces/p4/booking-390.png)다. 이 캡처를 직접 보았으며 첫 행의 13일에만 `예약 마감` 두 번째 줄이 있어 첫 행 세 버튼이 아래 행보다 높게 보인다. 이 정지 이미지로 당시 CSS 원인을 실측했다고 주장하지 않는다.

이번 진단은 스킬 문구와 조건 경계 중심이다. 최신 앱의 날짜 치수만 브라우저에서 추가 실측했으며 전체 화면 시각·행동 게이트를 대신하지 않는다.

## 적용 과제와 실제 진단 답

| 과제/반례 | 적용 답 | 판독 |
|---|---|---|
| 같은 날짜 그리드에서 한 날짜에만 상태 문구가 붙는다 | 기본/선택/불가의 외곽과 레이블 기준선, 부모 stretch 및 형제 높이를 함께 확인한다. 불가만 알려도 충분한 이번 날짜에는 사용자 요구대로 추가 보이는 문구를 제거하고 disabled 표현을 적용하며 접근성 이름의 날짜·사유를 보존한다. | 부모/형제 영향이 상태 필드와 연결되어 있다. 개별 버튼 box만 보는 진단보다 범위가 명확하다. |
| 일반 본문이 길어짐/이용자가 긴 메모 입력/상세 펼침 | 내용에 맞게 높이를 늘린다. 반복 선택 컨트롤의 상태 안정성을 이유로 고정 높이나 overflow 잘림을 적용하지 않는다. | 반례가 본문에 명시되어 과잉 적용을 막는다. |
| 선택 불가 사유가 다음 행동에 필수인 경우 | 예: 준비물 누락으로 선택 불가라면 사유를 없애지 않는다. 모든 항목의 설명 공간 또는 그룹에서 해당 항목과 연결된 보이는 설명을 마련한다. aria-label만으로 옮겨 일반 사용자에게 필수 사유를 숨기지 않는다. | ‘선택 불가만 전달하면 충분’ 조건과 ‘설명이 판단에 필수’ 조건을 구별할 수 있다. 이번 마감 문구 제거를 모든 사유 삭제 규칙으로 만들지 않는다. |
| 조건 태그가 본문을 반복함 | 같은 화면 항목 안에서 `10kg 이하`가 태그에 있으면 본문에서 동일 조건을 중복하지 않는다. `이동가방 필수`·`실내 동반 불가`·`사전 확인` 같은 별도 조건은 유지한다. 상세 화면에 재확인 정보가 필요하면 화면 역할을 구별한다. | 의미 중복을 줄이는 지침이 조건 손실 허가로 해석되지 않는다. |
| 발바닥/집 아이콘이 권한·검증을 보장하는 것으로 보일 수 있음 | 아이콘은 입장 공간·동물 조건을 식별하는 정적 정보다. 검증/인증/안전 완료 체크로 바꾸거나 `동반 가능`으로 제한 조건을 뭉개지 않는다. 알 수 없는 실제 권한은 가능으로 확정하지 않는다. | 새 계약의 보장 오해 방지와 역할 구분에 맞는다. |
| 닫힌 select만 제품 토큰으로 꾸미고 옵션은 native | 닫힌 필드의 여백·현재값·화살표·focus/disabled를 검증하고 실제 옵션은 native라고 보고한다. 전체 커스텀 팝업 구현 또는 검증으로 부르지 않는다. 키보드 선택은 별도 실행 결과가 있어야 통과시킨다. | 구현 범위가 명시돼 정적인 외관 확인을 팝업 행동 PASS로 확대하기 어렵다. |
| 다른 목록은 여백만으로 항목 경계가 충분함 | 교대 배경을 자동 적용하지 않는다. 내용·행동 묶음과 다음 항목 구분을 실제 스크롤 상태에서 판단하고 필요할 때 표면 단계를 선택한다. | 이번 P5 교대 배경은 사례 선택이며 모든 목록 공통 규칙이 아니다. |

## 최신 앱에서 실행한 좁은 실측

Playwright의 Chrome으로 `http://localhost:4190/round-04/app.html`을 열고 온실 커피의 9월 12일 13:00 예약 선택 버튼으로 날짜 면을 열었다. 브라우저의 임시 DOM에서만 측정/글자 확대를 수행했고 앱 파일을 변경하지 않았다.

| CSS viewport 폭 | 조건 | 날짜 7개 높이 | 폭 | 불가 날짜 |
|---|---|---|---|---|
| 390 | 기본 14px | 모두 44px | 약 111.33px | 13일 disabled, 접근성 이름 `13일 (일) 예약 마감` |
| 320 | 기본 14px | 모두 44px | 88px | 동일 |
| 390 | DOM 글자 확대 스트레스 | 모두 88px | 약 111.33px | 동일 |
| 320 | DOM 글자 확대 스트레스 | 모두 112px | 88px | 동일 |

확대는 `#booking *` 각 요소의 당시 computed font-size를 2배로 설정했다. 상속/자식별 설정이 섞이는 스트레스 검사로, OS 글자 200% 또는 브라우저 줌 200%의 정확한 재현이라고 부르지 않는다. 날짜 버튼 computed font는 28px였으며 같은 폭에서 disabled 날짜만 별도로 커지는 현상은 없었다. 이 결과는 일반 본문/필수 설명의 잘림이나 모든 모달 접근성을 검증하지 않는다.

`SELECT` 네이티브 요소인 것도 확인했다. `ArrowDown→Tab` 및 별도 fresh page에서 `Space→ArrowDown→Enter`를 시도했으나 인원 값이 2→2로 유지됐다. 자동화에서 실제 선택 변경을 확인하지 못했으므로 키보드 선택 PASS로 보고하지 않는다. 이 두 시도만으로 실제 사용자가 선택할 수 없다고 판정하지도 않는다. 네이티브 팝업의 시각 커스텀 검증은 수행하지 않았다.

정적 최신 app.js 판독에서는 실내 동반/10kg 이하 태그와 이동가방 필수 본문, 마당 동반/크기 제한 없음 태그와 실내 동반 불가 본문, 맹견 전용 대관과 단독 이용/입장조건 사전 확인 정보가 분리되어 있었다. 표본 데이터에서 필요한 서로 다른 조건을 제거한 흔적은 발견하지 못했다. 데이터 추가 시 조건이 달라지는 경우와 태그의 실제 시각·아이콘 인식은 이 정적 판독의 검증 범위 밖이다.

### 잔존 충돌 수정 재확인

부모 수정 후 `skills/design-md/references/document-contract.md:28`을 다시 읽었다. 절대14px 하한이 기본14px와 검증된 짧은 보조정보의 제한적12px 예외로 바뀌었고, 외부 예시12px의 자동 복사를 허용하지 않는다. 해당 글자 기준의 로컬 파일과 `#글자-크기-하한` fragment가 실제 존재함을 확인했다. 앞서 발견한 이1건의 문서 일관성 공백은 해소됐다. 과거 발견 기록은 보존한다. 전체 검사나 실제 렌더는 반복하지 않았으며 design-md quick_validate PASS는 부모 보고로만 구별한다.

## 최종 제품 검증 결과

catalog v5의 활성75개와 프로젝트10개,총85개 게이트는58통과/21범위명시예외/6미적용으로 PASS다. 부모도 최종CLI를 재실행해 errors/failures0을 확인했다. 독립 제품 검토는390/320·확대/고대비·기존예약흐름과가로시간의터치/휠/Tab/끝시간선택·요약/수정복귀를 실행했다. 실제모션/포커스도확인했고청색위청색focus발견→흰inset수정→재검증을보존했다.

12px는 목록 조건 태그와 반복조건요약만, 행동/가격/입력/상세·예약조건은14px이상으로 검증했다. [게이트 판독](../../design/reference-language/round-04/gate-review.md)과 [결과](../../design/reference-language/round-04/gate-result.json)에 범위와 근거가 있다. 판독기코드는수정하지않았으며catalog변경에따른기존unit21개는PASS했다. 수정스킬5개형식,최종보드3폭과문서링크/공백을확인했다. 이결과로실물폰/실예약/OS팝업방향키나새독립스킬반복평가를통과처리하지않는다.
