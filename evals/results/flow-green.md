# 이메일 가입 플로우 — 개발 전달안

상태: **spec-only / 모든 실행 검증 not-verified**. 오늘 전달 가능한 UI 계약이며, API 의존 전이는 계약 확정 전 연결할 수 없다. 질문 없이 아래 가정으로 진행한다.

대상은 이메일로 처음 가입하는 사용자와 기존 계정 사용자다. 플랫폼은 미정이며 브라우저 페이지를 가정한다. 시작은 가입 페이지, 완료는 서버가 계정 생성 및 필요한 인증 완료를 확인한 시점이다. 완료 후 제품 진입 위치는 미정이다. 수집은 이메일과 확정된 필수 인증 정보로 제한하며, 인증 방식·필수 동의 항목은 아직 정하지 않는다. 선택적 마케팅 동의는 기본 해제하고 거절해도 가입할 수 있다.

## 근거

| ID | 확인 범위 | 분류 |
|---|---|---|
| R2/O1 | 개인정보 동의 화면 한 장이 관찰되었다는 요청의 설명. 원본·세부 문구는 이번 전달에 없음 | user-reported; 직접 observed 아님 |
| Q1 | 이메일 가입, 선택 마케팅 동의, 네트워크 복구, 기존 계정 처리 | required |
| P1 | 아래 화면 순서·처리·복구 정책 전체 | proposed |

R2는 전후 순서, 가입 성공 조건, 실제 필수 동의의 근거가 아니다.

## 전이 계약

공통 보존 D: 이메일·동의는 열린 페이지의 메모리에서만 유지한다. 새로고침·종료 후 복원은 보장하지 않는다. 인증 비밀은 필요한 동안만 메모리에 두고 영구 저장하지 않는다. 어떤 상태에서도 뒤로·닫기가 서버 요청 취소를 뜻하지 않는다.

| ID | 출발·트리거/가드 | 처리 → 성공 | 실패·미상 | 보존·뒤로·재진입 |
|---|---|---|---|---|
| T1 | S1 계속 / 이메일 형식 유효, 확정된 인증 조건 충족 | 로컬 검증 → S2 | 입력 오류 S1, 해당 필드에 설명 | D; 재진입은 T7 |
| T2 | S2 가입 / 확정된 필수 조건 충족, 제출 없음 | 즉시 S3로 전환·반복 클릭 차단 → 완료 확인 시 S6 | 미처리 확정 S4E; 타임아웃·연결 단절 S4U; 정책상 기존 계정 분기가 확인되면 S5 | D; 처리 중 뒤로 와도 재제출 잠금 유지 |
| T3 | S2 뒤로 / 제출 전 | 요청 없이 S1 | 없음 | D; 다시 S2에서 선택 유지 |
| T4 | S4E 수정 또는 재시도 / 서버가 재시도 가능함을 보장 | 수정 S1/S2; 재시도는 T2 적용 | 동일 오류 S4E; 결과 불명 S4U | D; 뒤로 S1, 재진입 T7 |
| T5 | S4U 확인 / 실제 상태 조회 지원 시에만 | 조회 중 잠금; 완료 확인 S6, 미처리 확인 S4E | 조회 실패·조회 미지원·처리 중이면 S4U 유지 | D; 뒤로 S1에서도 제출 잠금. 자동 재제출 금지 |
| T6 | S1 로그인 선택 또는 기존 계정 분기 → S5 | 기존 인증 처리 → 인증 성공 시 제품 진입 | 기존 인증의 오류·복구 상태 | 가입 요청 없음; 뒤로 S1. 기존 경로의 보존 정책 적용 |
| T7 | 모든 상태에서 페이지 재진입 | 검증 가능한 유효 인증이면 제품 진입; 그 외 S1 | 인증/가입 상태 확인 불가이면 완료·실패로 단정하지 않음 | D 소멸; 자동 제출 없음. S1에 이전 가입 시도용 로그인·복구 진입 제공 |

S3 응답이 계정 생성만 확인하고 필수 인증이 남았다고 하면 S6로 가지 않는다. 인증 단계 및 추가 S/T는 실제 계약 확정 후 보완한다.

## 반례: 응답 유실 + 조회 API 없음 + 페이지 다시 열기

열린 페이지에서는 S4U를 유지할 수 있지만 재진입 후에는 메모리 소멸로 이전 요청의 존재도 식별할 수 없다. 지금 확정할 것은 **자동 재제출 없음, 성공·실패 단정 없음, 이전 시도 사용자를 위한 기존 로그인·복구 안내**다. 서버 미처리 확인·멱등성 보장이 없는 새 가입 제출의 중복 안전성은 보장할 수 없다. 지속적인 미상 상태 식별과 안전한 재시도는 저장 정책·요청 식별자·서버 중복 처리 계약의 미해결 의존성이다.

## 구현 경계와 검증

- Do: 필수/선택 구분, 제출 잠금, 확정 오류와 미상 분리.
- Avoid: 마케팅 강제, 동의 문구·보관 기간 복제, 미상 결과 자동 재시도.
- Intentional differences: R2 앞뒤에 우리 요구를 위한 입력·복구·완료 상태 제안. 환영 화면·불필요한 프로필 수집 없음.
- Unknown: 실제 동의 정책, 인증 방식, 기존 계정 노출 정책·로그인 목적지, 완료 응답, 오류 분류, 조회·멱등성·재진입 저장 정책. API endpoint는 가정하지 않았다.

인수 시나리오(모두 not-verified): T1→T2에서 마케팅 거절 후 완료 가능; 잘못된 이메일은 S1 유지; T3 왕복 시 D 유지; S3 반복 클릭은 요청 한 번; 미처리 확정은 T4, 응답 유실은 T5로 분리; T6은 신규 가입 없이 인증; T7에서 자동 제출 없음 및 위 반례의 불확실성 유지.
