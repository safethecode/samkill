# Round4 누적 피드백의 스킬 대응 감사

2026-09-10. 사용자 요청은 지금까지의 교정을 빠짐없이 스킬에 정리하는 것이다. 범위는 레퍼런스 분해/재현 실험과 Round4 P1–P12의 UI 교정, 작업 기록·커밋 운영이다. 아래는 현재 대화의 요구를 추적하는 감사표이며 제품의 새 렌더 검사나 새 독립 생성 실험 결과가 아니다.

## 이번 감사에서 보완한 부분

- 기존 원칙 대부분은 이미 있었지만 스킬 진입점→실제 검수의 연결이 약했다. 위 대응표와 재발 점검을 연결해 누락을 추적한다.
- 포인터 초점 문단을 여백 절에서 경계/포커스 절로 옮겼다.
- 범용 주 제목 기준에 남은 특정 제품의24px 출발점을 해당 제품 토큰으로 바꿨다. 크기/위계를 없앤 것이 아니다.
- 새 렌더 검증 없이 해시만 새로 계산하거나 바뀐 DOM/문구의 옛 PASS 이유를 현재 판정으로 남기는 것을 재발 점검에서 명시적으로 금지했다.
- 신규 공통 실패 규칙 ID/임계값은 만들지 않았다. 기존 RUI 기준에 교정별 판독과 증거를 연결하므로 catalog version은 그대로다.

## 검증과 한계

RED 근거는 사용자에게 실제로 거절된 Round4/P5–P12의 순차 실패와 보존된 자료다. 원본 코드·렌더·검증은 [제품 리뷰](../../design/reference-language/round-04/review.md)에 있다. 이번에는 앱을 다시 구현하거나 그 결과를 새 테스트처럼 꾸미지 않는다.

기존 맥락을 아는 보조 감사가 관리원본을 읽고 누락 경로·문단 위치·과도한 고정값을 찾아 부모에게 보고했다. 새 fresh 독립 구현/반복5회 실험이 아니다. 형식·링크·내용 대응 감사는 문서의 발견 가능성과 일관성을 확인하며 다음 제품의 무재발을 보증하지 않는다.

### 보조 재감사와 적용 시나리오

기존 문서 맥락을 아는 보조 감사가 수정 후 연결/포커스 위치/24px 일반화의 해소를 확인했다. 새 문구의 네이티브 disabled 구현 강제 가능성과 빈 원인별 행동 강제 차등을 발견해 기능·의미 및 원인에 맞는 복구 기준으로 좁혔다.

- 정확한 복제 요청: 이 사례의gray50/붉은취소/20px를 강제하지 않는다. 원본 관계와 사용자 제약을 따른다.
- 저장1개/확대20개: 들어가는 짧은 내용은 불필요한 스크롤0, 넘치는 내용은 접근 가능한 스크롤 유지다.
- 중복 그룹제목·취소상태, 실제 결과가 바뀌지 않는 기간 필터: 정보 중복과 행동 불일치를 통과시키지 않는다.

이는 문서 적용 시나리오 점검이며 새로운 UI 구현 성공률 측정이 아니다. 관리 스킬3개 형식 검사, 변경 문서의 로컬 링크/앵커126개, 공백 검사를 수행했다.

설치된 reference-to-ui/reference-decompose/reference-review 경로가 관리원본 skills/를 가리키는 것도 확인했다. 별도 사본 배포나 앱 코드 변경은 없었다.
