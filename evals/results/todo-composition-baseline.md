# 실제 Todo 결과: 사용자 피드백과 기존 판독 누락

2026-09-06. 새 규칙 이전에 사용자가 스킬을 시험해 만든 `todo/`를 읽기 전용으로 확인했다. 이 실행이 모든 스킬을 어떤 순서로 읽었는지는 현재 자료만으로 확정하지 않는다. 새로 만든 무스킬 baseline이나 통제 실험이라고 표시하지 않는다.

원래 요청은 [평가 사례 J](../cases.md)에 보존했다. 사용자가 첨부한 4개 부분 화면을 직접 확인했고, 프로젝트가 저장한 전체 모바일 화면 2장도 직접 열어 확인했다. [초기 화면](../fixtures/todo-feedback/mobile-initial.png), [대화 후 화면](../fixtures/todo-feedback/mobile-chat.png), [파일 해시와 코드 사실](../fixtures/todo-feedback/manifest.json)을 별도로 보존했다. 원래 todo 소스와 리뷰 파일은 수정하지 않았다.

| 규칙 | 확인된 자료와 판단 | 재검증할 것 |
|---|---|---|
| RUI-08 | header에 직접 만든 체크 마크와 ‘오늘’, ‘가볍게, 하나씩’. 요청에 브랜드 제작은 없고 기존 리뷰는 자체 로고 geometry/identity로 정당화했다. 사용자도 임의 로고를 거부했다. | 브랜드 요청 없이 화면 제목과 필요한 정보만 남는지 |
| RUI-09 | tokens.css의 --size-sm:12px가 필터·편집·시간·힌트·대화 등에 연결된다. 화면 픽셀로 CSS 크기를 추정한 결과가 아니다. | 실제 computed size가 상태/폭마다 14px 이상인지 |
| RUI-10 | 전체/할 일/완료 선택 그룹과 같은 줄 오른쪽 ‘편집’이 회색 텍스트만으로 보인다. 실행과 필터의 표현이 구별되지 않는다. | CTA를 표면/윤곽 또는 의미 있는 아이콘+라벨로 구분했는지 |
| RUI-11 | 제목 오른쪽 힌트, 안내 메시지, 예시 칩, 입력 아래 설명이 같은 생성 영역에 쌓였다. 저장 안내·슬로건까지 상단에 분산된다. | 삭제 가능한 문구를 덜고 필요한 정보만 입력/행동 근처에 두는지 |
| RUI-12 | 브랜드·대화·빈 상태의 inline SVG 경로를 직접 작성했다. 기존 코드는 색/선 스타일 일치를 검사했지만 아이콘 선택과 출처의 타당성은 충분히 남기지 않았다. | 기존/출처 있는 세트의 적절한 기능 아이콘과 접근 가능한 이름 |
| RUI-13 | 최종 CSS는 app 100dvh/overflow:hidden, planner overflow-y:auto, conversation max-height:160px/overflow-y:auto. 기존 리뷰는 4개 중 3행만 초기 표시된다고 기록한다. ‘길어질 수 있다’는 설명으로 목록/대화의 동시 압축을 수용했다. | 실제 빈/1개/소수/긴 목록에서 가용 높이·scrollHeight, 키보드와 큰 글자. 이번에 실시간 스크롤은 실행하지 않음 |
| RUI-14 | HTML hr 태그가 아니라 brand-bar/week/task의 border-bottom과 chat의 border-top이 반복 구분선을 만든다. 태그 검색만 하면 놓친다. | 선을 간격·정렬·묶음으로 바꾸되 버튼/입력 경계·focus 보존 |
| RUI-15 | 목록과 대화가 한 프레임에 항상 함께 있고 대화는 작은 결과 피드로 제한된다. 사용자는 채팅이 자연스럽지 않으며 별도 탭도 충분했다고 지적했다. | 목록/대화 구조 비교, 전송·실패·복귀·초안 보존·과거 대화 읽기 실제 실행 |

문구의 필요성 및 채팅 불편은 사용자 평가와 화면 맥락을 근거로 한다. 정지 화면으로 전환·키보드·스크롤 행동을 실행했다고 주장하지 않는다. 새 기준에서 이 기존 결과는 재작업 대상이며, 수정 완료로 표시하지 않는다.

기존 `todo/design/review.md`의 총괄은 aligned다. 그러나 `todo/design/gate-result.json`의 실제 저장 결과는 UNVERIFIED이며 `design/gate-contract.json` 경로를 찾지 못한 오류다. 자동 게이트가 이 UI를 PASS시켰다고 주장하지 않는다. 문서의 긍정 판정과 실제 CLI 결과가 일치하는지도 완료 시 확인해야 한다.

수정 방향은 [UI 구성 기준](../../skills/reference-to-ui/references/ui-composition.md)에 연결했다. 원래 기준을 삭제하지 않고 RUI-08–15를 추가해 catalog version을 1에서 2로 올렸다. 이전 판독/해시는 새 기준의 완료 증거로 재사용할 수 없다.

후속 사용자 교정: 결과가 레퍼런스와 닮지 않고 품질도 부족하며 좋은 부분을 결합해야 한다는 평가를 받았다. `reference-brief.md`와 `design-contract.md`를 대조하면 체크/날짜라는 기능과 chosen 값 위주로 인계되고, 원본의 핵심 시각 관계가 유지됐다는 구현 비교가 부족하다. 원본 이미지를 이번 검토에서 새로 열지는 않았으므로 사용자 평가와 문서에서 확인한 공백을 분리한다. RUI-16/17과 Q-ID 비교 절차를 추가했다.
