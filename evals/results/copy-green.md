# 오늘 시연용 UX 문구

지금 확정해서 쓸 제목은 **“결제에 문제가 발생했어요”**입니다. 기존 초안의 “잠시”는 원인이나 지속 시간을 알 수 없어 뺐습니다. 복구 행동이 정해지지 않아 “다시 시도해 보세요”와 참고 버튼 “다시 결제”는 확정하지 않습니다.

아래 key는 예정 key입니다. ‘ready’는 문구 전달 상태이며 실제 화면·행동 검증 완료를 뜻하지 않습니다.

| C-ID / 예정 key | 화면·상태 / 노출 조건 | 최종 UI 문구 | 연결 행동 | 사실 근거 | 상태 | 검증 |
|---|---|---|---|---|---|---|
| C1 / payment.issue.title | 결제 문제 화면 / 제공된 결제 오류 상황을 시연할 때 | 결제에 문제가 발생했어요 | 없음 | 사용자 요청과 기존 초안에서 결제 과정의 문제는 확인됨. 결제 완료 여부는 단정하지 않음 | ready | 원인·과금·복구를 단정하지 않는지 문구 검토 완료. 실제 상태 매핑·레이아웃·접근성은 not-verified |

**구현자 메모 — UI에 표시하지 않음**

- 설명은 추가하지 않습니다. 과금 여부와 원인이 unknown이라 확정해서 전달할 부가 정보가 없습니다.
- C2 / `payment.issue.action`: 최종 UI 문구 없음, 연결 행동 unknown, 상태 `blocked-on-fact`. 복구 행동이 확정되기 전 시연 화면에 활성 버튼을 임의로 넣지 않습니다. 참고 문구는 표현 사례이며 재결제 가능성을 입증하지 않습니다. 행동 검증은 not-verified입니다.
- C3 / `payment.failure.title`: 조건부 초안 **“결제를 완료하지 못했어요”**. 제품에서 결제 미완료가 확정된 상태에만 노출하며 연결 행동은 없습니다. 현재 근거는 ‘실패 화면’이라는 요청명뿐이라 상태는 `draft-dependent`입니다. 실제 상태 일치 검증은 not-verified입니다.
- 필요한 제품 사실은 오류 상태의 정확한 의미, 과금 여부, 사용 가능한 복구 행동입니다. 결과 미상과 확정 실패를 구분할 수 있어야 제목을 더 구체화할 수 있습니다.

## 짧은 반례: 검색 결과 0건

가상 조건: 조회는 성공했고 결과가 0건이며, 적용된 필터를 초기화하는 동작이 확인되어 있습니다.

| C-ID / 예정 key | 화면·상태 / 노출 조건 | 최종 UI 문구 | 연결 행동 | 사실 근거 | 상태 | 검증 |
|---|---|---|---|---|---|---|
| C4 / search.empty.title | 검색 / 조회 성공·결과 0건 | 검색 결과가 없어요 | 없음 | 가상 조건에서 실제 0건 확인 | ready | 0건과 조회 실패를 구분해 작성. 실제 노출·레이아웃·접근성 not-verified |
| C5 / search.empty.reset | 검색 / 결과 0건·필터 적용됨·초기화 가능 | 필터 초기화 | 적용된 필터 초기화 | 가상 조건에서 동작 확인 | ready | 라벨과 제공된 동작 일치 확인. 실제 실행·접근성 not-verified |

확인된 초기화 행동이 있으므로 버튼 문구까지 전달할 수 있습니다. 초기화 후 결과가 생긴다는 보장은 하지 않습니다.

**검증 한계:** 스크린샷과 브라우저가 없어 좁은 폭, 줄바꿈, 스크린리더 이름, 실제 노출 조건과 클릭 동작을 확인하지 못했습니다. 문구와 제공된 가상 사실의 일치만 검토했습니다.
