## 한국어 글쓰기 추가 요구

사용자 제공 토스 글의 8원칙을 한국어 질문·전후 예시·제품 사실 보존 검사로 반영했다. 댓글과 웹페이지 메뉴는 근거에서 제외했다. 기존 ux-copy로 먼저 실행한 [korean-copy-baseline.md](korean-copy-baseline.md)는 행동 예측·비용 공개·번역투 제거를 이미 잘 수행했다. 따라서 이를 실패라고 기록하지 않는다. 상환 완료는 사실만 전달했으며, 새 기준은 상황에 맞는 짧은 공감도 검토하도록 명시했다.

최종 변형 사례는 예시와 다른 설문·금액·날짜, 삭제 요청 접수와 완료의 구별, 가능성 표현을 사용했다. [korean-copy-green.md](korean-copy-green.md)를 직접 검토했다. 설문을 보상으로 표현하지 않았고, 12월 12일·7,900원·매월 조건을 보존했다. 삭제 요청 접수와 7일 이내를 삭제 완료/정확히 7일 후로 바꾸지 않았고 ‘없을 수 있어요’의 가능성을 유지했다. 확인된 상환 완료에는 짧은 축하를 더했으며 확인되지 않은 노력·보상은 만들지 않았다. 8원칙별 적용 근거가 남았고 실제 렌더·동작 검증은 미완료로 표시됐다.

## 해석의 한계

- 행동 평가는 합성 입력을 사용한 독립 에이전트의 실제 산출물을 읽어 판정했다. 예시와 일부 평가 입력이 유사하므로 일반화 효과를 과장하지 않는다.
- 조건별 5회 이상 fresh-context 반복 실험이나 통계적 비교는 수행하지 않았다.
- 실제 MCP 테스트는 연결·조회·정지 화면 관찰을 검증했다. UX 효과·전환율·서비스 전체 화면/동작을 검증한 것이 아니다.
- 실제 앱 구현, 브라우저 렌더 A/B 비교, 모바일 기기/스크린리더 검증은 이번 스킬 제작 범위에서 수행하지 않았다. 향후 이 스킬로 만든 UI에서 별도 검증해야 한다.
- 개인 경로가 정확한 원본을 가리키는 것은 확인했다. 현재 대화에 이미 로드된 스킬 목록의 실시간 재갱신까지 확인한 것은 아니다.

## 상세 UI·토큰·판독기와 본질 중심 설계 추가

상세 여백·버튼 색 조합·아이콘 및 실제 토큰 사용은 [상세 분석/토큰 평가](component-tokens-green.md)에 기록했다. 원본 실패 50개와 추가 기준 7개를 보존하고, 판독기 CLI 21개 테스트와 원본 대조를 수행했다. [추가 검증 범위](design-gate-summary.md), [현재 형식 검사](structure-current.json)를 참고한다. 위 초기 형식 검사 11개 링크는 당시의 기록이며 현재 검사는 33개다.

본질·레퍼런스/아이디어 결합·실패 삭제 압박·브랜드 예외·anti-slop은 [독립 합성 평가](essence-gate-green.md)에서 확인한다. 이 결과를 실제 제품 구현이나 렌더 검증으로 대체하지 않는다.
