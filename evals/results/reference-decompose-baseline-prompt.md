다음 명세로 모바일 여행 일정 편집 화면을 구현하라. 구현자가 이미지를 보지 않아도 화면의 구조, 요소의 관계, 표시 상태와 동작을 이해할 수 있도록 아래 설명을 기준으로 작업한다. 반려동물 서비스나 다른 제품으로 각색하지 않는다.

출처 R1은 `design/pet-course/references/celetrip.png`이며, 직접 확인한 단일 정지 화면이다. 관찰 좌표는 화면에 표시된 약 295 × 640 image-px 기준의 시각 추정이다. 원본 CSS viewport, DPR, 서체, DOM, 정확한 색상과 간격은 unknown이다. 아래 `chosen` CSS 값은 구현을 위한 새 결정이며 원본 실측값이 아니다.

사용자의 핵심 행동은 날짜별 여행 장소를 살펴보고, 편집할 장소를 선택하거나 순서를 조정한 다음 수정을 완료하는 것이다. 이미지에서 확인되는 것은 기본 편집 화면과 비활성 완료 버튼이며, 선택 이후의 화면과 실제 저장 방식은 확인되지 않았다.

전체 화면을 다음 순서로 구성한다.

```text
여백을 포함한 모바일 상태 표시 영역
뒤로가기                 여행 일정 편집
Day 1  Day 2  Day 3

Day 1 (06.25)
[선택 상자] [장소 사진 | 지역명 / 장소 유형 | 순서 손잡이]

Day 2 (06.26)
[선택 상자] [장소 사진 | 장소명 / 지역명 / 장소 유형 | 순서 손잡이]
[선택 상자] [장소 사진 | 지역명 / 장소 유형 | 순서 손잡이]

Day 3 (06.27)
[아래로 이어지는 장소 카드 일부]

[                   수정 완료                   ]
```

O1: 상단은 중앙 제목, 왼쪽 뒤로가기, 아래쪽 날짜 탭으로 구성된다.
O2: 날짜별 제목 아래에 사진이 왼쪽에 붙은 가로 카드가 놓인다. 선택 상자는 카드 밖 왼쪽, 순서 손잡이는 카드 안 오른쪽에 있다.
O3: 모든 날짜 섹션이 한 문서 안에 연속해서 보이며 Day 1 탭만 선택되어 있다.
O4: Day 2에 카드 두 개가 있고, Day 3은 제목과 첫 사진 일부만 보인다.
O5: 하단의 넓은 회색 완료 버튼은 현재 비활성 상태로 보인다.

보존할 핵심은 카드 외부의 선택 상자, 카드 왼쪽을 채우는 사진, 카드 내부의 작은 텍스트 묶음과 오른쪽 손잡이, 날짜 그룹 사이의 넉넉한 간격, 비활성 완료 버튼의 낮은 강조다. 원본의 작은 글씨를 그대로 축소하지 않는다. 읽는 글자는 모두 **14 CSS px 이상**으로 구현한다.

기존 프로젝트에 해당 역할의 토큰이 있으면 우선 사용한다. 없을 경우 다음 값을 `chosen` 토큰으로 정의한다.

| 역할 | 구현값 |
|---|---|
| 화면·카드 배경 | 흰색 |
| 주요 글자 | `#111111` |
| 보조 글자·아이콘 | `#7A7A7A` |
| 카드·선택 상자 경계 | `#E5E5E5` |
| 선택된 날짜 배경/글자 | `#111111` / `#FFFFFF` |
| 기본 날짜 배경/글자 | `#FFFFFF` / `#111111` |
| 비활성 완료 배경/글자 | `#BDBDBD` / `#FFFFFF` |
| 화면 좌우 패딩 | 20 CSS px |
| 날짜 탭 간격 | 8 CSS px |
| 카드 사이 간격 | 14 CSS px |
| 날짜 그룹 사이 간격 | 32 CSS px |
| 카드 반경 | 6 CSS px |
| 완료 버튼 반경 | 12 CSS px |

모든 읽기용 텍스트는 시스템 sans-serif로 시작한다. 정확한 원본 폰트는 unknown이다. 본문 14/20 CSS px, 화면 제목 18/26 CSS px, 날짜 제목 16/24 CSS px로 설정한다. 제목과 장소명·지역명은 600~700, 유형과 괄호 안 날짜는 400~500의 위계를 사용한다. 자간은 기본값으로 둔다.

각 요소를 다음 프롬프트 단위로 구현한다.

**E1 — 화면 프레임과 스크롤**

흰색 배경의 모바일 화면을 만든다. 구현 비교 기준 viewport는 `chosen` 390 × 844 CSS px다. 가로 스크롤을 만들지 않는다. 화면은 상단 헤더, 세로 스크롤 가능한 일정 영역, 하단 완료 영역으로 나눈다. 원본에서 헤더와 완료 영역이 고정되는지는 unknown이며, 구현에서는 세 영역을 분리하여 일정만 스크롤하게 한다.

부모 화면이 좌우 패딩을 소유한다. 날짜 탭, 날짜 제목, 선택 상자의 왼쪽과 완료 버튼의 왼쪽을 같은 기준에 맞춘다. 카드 자체는 선택 상자 열 다음에서 시작한다. 하단 일정이 완료 영역에 가려지지 않게 한다.

원본 상단에는 `3:31`, 통신·배터리 표시가 보인다. 실제 앱 환경에서는 운영체제 상태 표시 영역을 사용한다. 웹에서 재현하는 경우 약 34 CSS px 높이의 별도 비상호작용 영역으로 표현하고, 앱 내비게이션과 섞지 않는다. 상태 표시는 스크린리더에서 숨긴다. 장식용 로고나 슬로건을 추가하지 않는다.

**E2 — 편집 헤더**

높이 56 CSS px의 흰색 헤더 중앙에 `여행 일정 편집`을 둔다. 제목의 중심은 뒤로가기 버튼을 제외한 남은 공간의 중심이 아니라 화면 전체의 중심이다.

왼쪽에 공식 Lucide `ChevronLeft`를 사용한다. 아이콘은 회색 윤곽선, 표시 크기 20 CSS px, 클릭 영역 44 × 44 CSS px로 한다. 배경은 투명하고 테두리는 없다. 접근 가능한 이름은 `뒤로가기`다. 선행 방향 아이콘은 뒤로가기 관례에 따른 예외다.

이미지에서 오른쪽 행동은 보이지 않으므로 추가하지 않는다. 헤더 아래에 선이나 그림자로 구분선을 만들지 않는다. 원본의 아이콘 패밀리와 실제 stroke는 unknown이며 Lucide 사용은 저장소 기준에 따른 새 결정이다.

**E3 — 날짜 이동 컨트롤**

헤더 아래 20 CSS px 간격을 두고 왼쪽부터 `Day 1`, `Day 2`, `Day 3`을 배치한다. 세 개를 화면 전체 폭에 균등 분배하지 않는다. 내용 폭에 가까운 작은 캡슐 형태로 만들고 내부 좌우 14 CSS px, 표시 높이 32 CSS px, 글자 14 CSS px, 반경 999 CSS px를 사용한다. 터치 영역은 주변 여백을 포함하여 최소 높이 44 CSS px를 확보한다.

Day 1은 검정 배경에 흰색 글자, 나머지는 흰색 배경에 검정 글자와 옅은 회색 외곽 경계다. 아이콘은 없다. 선택 상태에 밑줄이나 이동 바를 쓰지 않는다.

모든 날짜 그룹이 화면에 함께 보이므로 구현에서는 날짜별 화면을 숨기는 탭 패널 대신 섹션 이동 버튼으로 만든다. 클릭하면 해당 날짜 제목으로 이동하고 현재 날짜의 캡슐 배경을 갱신한다. 이 이동 동작은 정지 이미지에서 확인되지 않은 `chosen` 동작이다.

**E4 — 날짜별 그룹 제목**

날짜 컨트롤 아래 24 CSS px 간격을 두고 첫 제목을 배치한다. 이후 그룹은 앞 그룹의 마지막 카드 아래 32 CSS px에서 시작한다.

제목은 각각 `Day 1 (06.25)`, `Day 2 (06.26)`, `Day 3 (06.27)`이다. `Day N`은 검정 굵은 글자, 괄호 안 날짜는 회색 보통 굵기로 표시한다. 같은 줄의 baseline을 맞춘다. 날짜가 출처에 없는 연도를 임의로 추가하지 않는다.

제목과 첫 카드 사이 간격은 12 CSS px다. 그룹 사이에는 수평선, border, pseudo-element, shadow 또는 gradient로 만든 동등한 장식선을 넣지 않는다.

**E5 — 선택 상자를 포함한 장소 행**

행은 세 열로 구성한다.

```text
20 CSS px 선택 상자 / 10 CSS px 간격 / 남은 폭의 장소 카드
```

선택 상자는 카드의 세로 중앙과 정렬한다. 기본 상태는 흰색 내부와 옅은 회색 1 CSS px 경계, 거의 각진 모서리다. 실제 조작 영역은 44 × 44 CSS px 이상으로 하되, 이 영역 때문에 카드의 왼쪽 위치나 행 높이가 불필요하게 밀리지 않게 한다.

이미지에서는 모두 미선택 상태다. 네이티브 checkbox 또는 동등한 키보드 조작을 제공하고, 접근 가능한 이름은 해당 장소를 포함한 `… 선택`으로 지정한다. 선택 상태는 구현에서 검정 채움과 흰색 체크로 새로 정의한다. 선택에 따른 삭제·이동 툴바는 이미지에 없으므로 추가하지 않는다.

카드는 흰색 배경, 옅은 회색 1 CSS px 외곽 경계, 6 CSS px 반경으로 만든다. 카드 경계는 영역 구분용 수평선과 역할이 다르므로 유지한다. 외곽 경계를 강조하는 무거운 그림자는 넣지 않는다.

카드 내부는 `사진 86 CSS px / 텍스트 가변 폭 / 손잡이 24 CSS px`로 나눈다. 최소 높이는 96 CSS px이며 내용에 따라 늘어난다. 사진은 카드의 위·아래·왼쪽 면에 붙인다. 텍스트 영역은 위·아래 10, 왼쪽 12, 오른쪽 6 CSS px 여백을 갖고 세로 중앙에 놓인다. 손잡이는 카드 오른쪽에서 8 CSS px 떨어진 위치에 세로 중앙 정렬한다.

**E6 — 장소 사진과 실제 텍스트**

Day 1에는 카드 하나를 둔다. 사진은 붉은 기둥과 간판이 있는 작은 상점의 정면이다. 텍스트는 굵은 `Jingūmae, Shibuya`, 그 아래 회색 `Activity` 두 줄이다. 별도 장소 제목은 보이지 않으므로 생성하지 않는다.

Day 2 첫 카드는 붉은 외벽과 간판이 있는 거리 상점 사진이다. 장소명은 이미지 판독상 `와라타코 하라주쿠 오모테산도점`으로 보이나 정확한 표기는 추가 확인이 필요하다. 구현 데이터의 잠정 표기로 사용하고 확정된 원문이라고 기록하지 않는다. 좁은 폭에서는 장소명을 두 줄로 자연스럽게 감싼다. 그 아래 `Jingūmae, Shibuya`, 다음 줄에 회색 `Restaurant`를 둔다. 텍스트를 맞추기 위해 14 CSS px 아래로 줄이지 않는다.

Day 2 두 번째 카드는 어두운 처마와 따뜻한 조명, 붉은 출입구가 보이는 식당 사진이다. 굵은 `Dōgenzaka, Shibuya` 아래 회색 `Restaurant`를 둔다. 별도 장소 제목은 보이지 않는다.

사진은 `object-fit: cover`로 영역을 채운다. 원본 래스터에서 사진을 추출할 수 있다면 대략 첫 사진 x=42–112, y=183–253, 두 번째 x=42–112, y=315–387, 세 번째 x=42–112, y=402–473 image-px 부근을 확인하여 사용한다. 이 좌표는 시각 추정이므로 원본 이미지 크기를 먼저 확인하고 경계가 포함되지 않게 보정한다. 출처 이미지 자체를 통째로 화면 배경에 깔아 구현을 대신하지 않는다.

Day 3은 제목 아래 카드 상단과 사진 일부만 보인다. 장소명, 유형, 카드 개수는 unknown이다. 검증된 데이터가 없으면 임의의 장소명을 만들어 넣지 않는다. 첫 비교에서는 확인된 부분만 표현하고 나머지 데이터는 미확인으로 남긴다.

**E7 — 순서 조정 손잡이**

각 카드 오른쪽에 회색 점 여섯 개가 두 열로 보이는 손잡이가 있다. 공식 Lucide `GripVertical`을 18 CSS px로 사용한다. 별도 배경이나 테두리는 없다. 카드 오른쪽 끝에 붙이지 않고 앞서 정의한 내부 여백을 유지한다.

정지 이미지로 드래그 작동 여부는 확인되지 않았다. 구현에서는 같은 날짜 안에서 순서를 조정하는 컨트롤로 연결한다. 포인터 드래그와 키보드 조작을 모두 지원하고, 이동 결과를 보조기기에 알린다. 날짜 간 이동 규칙은 추가하지 않는다. 손잡이만 장식으로 놓고 작동한다고 보고하지 않는다.

**E8 — 완료 영역과 상태**

화면 아래에 흰색 완료 영역을 둔다. 좌우 20 CSS px, 위 20 CSS px, 아래 `20 CSS px + safe-area-inset-bottom` 여백을 사용한다. 넓은 `수정 완료` 버튼은 너비 100%, 높이 52 CSS px, 회색 배경과 흰색 16 CSS px 굵은 글자, 12 CSS px 반경이다. 아이콘은 없다.

기본 화면에서는 실제 `disabled` 상태다. 변경 사항이 생기면 검정 배경과 흰 글자의 활성 상태로 전환한다. 이 활성 상태와 저장 규칙은 원본에서 확인되지 않은 구현 결정이다. 완료 시 연결된 저장 핸들러를 실행하며 저장 중에는 중복 실행을 막는다. 서버 연결이 없다면 저장 완료를 허위로 표시하지 않는다.

원본 하단 경계에 희미한 선이 보이더라도 저장소 규칙에 따라 재현하지 않는다. 완료 영역과 일정의 관계는 흰색 표면, 여백과 배치로 표현한다.

모든 버튼·경계 상태 변화는 `chosen` 150ms ease-out으로 연결하되 크기와 내용 위치를 바꾸지 않는다. 키보드 포커스는 식별 가능한 outline 또는 inset shadow로 표시한다. `prefers-reduced-motion`에서는 이동 애니메이션을 줄인다. 원본의 hover, focus, pressed 색상은 unknown이다.

첫 렌더에서는 다음을 대조한다.

- Q1/R1/O1/E2–E3: 중앙 제목과 왼쪽의 작은 날짜 캡슐이 유지되는가.
- Q2/R1/O2/E5–E7: 선택 상자가 카드 밖에 있고 사진·텍스트·손잡이가 서로 다른 열을 유지하는가.
