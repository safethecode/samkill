# 입력 컨테이너 포커스 규칙 평가

2026-09-20. 평가 범위는 변경 지침의 수동 시나리오 대조다. 독립 에이전트 실험·제품 구현·브라우저 검증은 수행하지 않았다.

기존 실패: 중복만 없으면 입력 자체에 링을 남기거나 border 색 전환으로 대체할 수 있었다. 토큰 계약과 구성·리뷰 기준이 이제 표시 위치와 구현 방식을 함께 지정한다.

| 시나리오 | 변경 지침에 따른 판정 | 근거 |
|---|---|---|
| 검색 input 자체에 inset shadow, 래퍼는 그대로 | 실패 | 표시 주체는 필드 컨테이너 |
| 래퍼 border 색만 변경 | 실패 | 일반 색상 모드의 입력 초점은 inset box-shadow |
| 래퍼 inset, 내부 기본 링 제거, 실제 초점은 input | 규칙에 부합 | 위치·방식·입력 기능 분리 |
| 전송 버튼 초점에도 focus-within으로 입력 강조 유지 | 실패 | 입력 초점에만 래퍼 표시, 버튼 대상 식별 |
| 입력 blur 후 wrapper tabindex로 초점 이동 | 실패 | DOM 초점과 caret 보존 |
| 기본·오류 border는 고정하고 초점에 inset 추가 | 규칙에 부합 | 기본/오류 경계는 금지 범위 밖, 이중선은 별도 검증 |
| forced-colors에서 컨테이너 시스템 outline 대체 | 허용 | shadow 소실에 대한 제한된 대체 표시 |
| 버튼과 링크의 기존 focus-visible outline 유지 | 허용 | 입력 전용 규칙을 다른 조작에 확대하지 않음 |

판정은 지침의 적용 결과이며 화면 PASS가 아니다. 실제 적용 시 클릭·Tab/Shift+Tab·오류+focus·blur·고대비에서 표시 주체, 이중선, 외곽/텍스트/줄바꿈 불변을 확인해야 한다.
