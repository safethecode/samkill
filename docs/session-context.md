# Codex 대화 맥락과 결정 기록

최초 정리: 2026-09-06. 이 문서는 현재 Codex 세션에서 스킬 제작을 요청하고 기준을 구체화한 대화를 요약한다. 전체 대화의 축어록이 아니며, 요청·구현 결정·검증 사실을 구분한다. 이후 중요한 변경은 날짜별 후속 기록으로 추가한다.

## 출발점과 목표

사용자는 UIbowl MCP로 레퍼런스를 가져와도 구현에 충분히 활용하지 못한다고 느꼈다. 다양한 작업에 재사용할 스킬과 보일러플레이트를 만들고, `/Users/aaron-son/Documents/orchestrator`의 레퍼런스 기반 설계 방식을 분석해 반영해 달라고 요청했다.

사용자가 명시한 최종 목표는 “AI스러운 디자인에서 벗어나 레퍼런스와 아이디어를 잘 섞어서 좋은 디자인으로 제품을 구현하는 것”이다. 이를 고객 문제 정의 → 레퍼런스 상세 관찰 → 채택·배제·새 아이디어 결정 → 토큰 기반 구현 → 실제 비교·실패 누적의 작업 흐름으로 구체화했다.

실제 관리 원본은 현재 저장소 `samkill/skills/`에 있다. orc는 분석 입력이며 수정하지 않았다. 개인 `~/.codex/skills/`의 다섯 연결은 이 저장소를 가리킨다. 경로를 이동하면 연결도 확인해야 한다.

## 외부 자료를 사용한 범위

orc의 `profiles/design.md`와 `profiles/design-components.md`를 로컬에서 분석했다. 실패 목록에는 Known AI Failure Patterns 16개, QA Guardrails 24개, AI Slop 체크리스트 10개를 원문과 함께 보존했다. 추가 RUI 기준 7개는 이 패키지의 작업 기준이며 orc 원문으로 표시하지 않는다. 이 수량은 최초 정리 시점의 상태이며 이후 목록 버전에 따라 달라질 수 있다.

사용자가 제공한 토스 글의 원칙은 다음 행동 예측, 불필요한 단어 제거, 중복 문장 제거, 핵심 정보 집중, 말하기 쉬운 표현, 강요 없는 권유, 누구나 이해할 말, 상황에 맞는 공감이다. 토스의 최신 공식 정책을 별도로 검증했다고 주장하지 않는다.

[anti-slop](https://github.com/dmmulroy/anti-slop/tree/e8c4880471b23ab7f216fba7b27d173a6ef07d4c)은 해당 revision의 README·설치 스킬·일반 규칙 등록 코드를 확인했다. upstream의 최신 변경은 향후 적용 시 재확인한다. 현재 저장소에는 제품 TS/JS 구현이 없어 Oxlint/anti-slop을 설치·실행하지 않았다.

[Douglas 자료](https://github.com/team-attention/openclone/blob/40d0586541418b1a27eae4f8ac4352b78c8e4062/clones/douglas/persona.md)는 해당 revision의 persona와 고객 문제·가치·본질에 관련된 지식 5편을 읽었다. 개별 출처는 [적용 문서](../skills/reference-to-ui/references/product-reasoning.md)에 있다. 전체 지식 폴더를 읽었다고 주장하지 않는다. 인물의 말투나 정체성, 투자 조언을 가져오지 않고 고객 문제 중심 관점을 UI 판단에 응용했다.

## 반드시 보존할 교정

원본 금지 사항을 “그 자체는 결함이 아니다”라며 일괄 해제하는 것은 사용자의 의도와 다르다. 원본 실패를 먼저 검사하고, 명시된 브랜드·접근성·사용자 과제로 예외가 필요하면 관련 ID와 범위·근거·검증 결과를 남긴다. 반대로 금지 목록만 따라 모든 제품을 같은 회색 화면으로 만드는 것도 목표를 충족하지 않는다. 제품의 핵심 과제와 디자인 품질을 각각 확인한다.

독립 합성 평가에서 명세 전용 작업의 게이트 처리에 모호함이 발견됐다. 게이트 문서에 RUI-07 예시를 추가해 원래 `spec, visual` 검사 종류를 유지하고 화면이 없으면 `unknown`으로 남기도록 보완했다. 명세는 `spec-only`로 전달할 수 있지만 구현 게이트 PASS는 아니다. 원래 지적과 후속 확인을 [평가 기록](../evals/results/essence-gate-green.md)에 함께 보존했다.

최초 다섯 스킬·문서·템플릿·평가 기록은 `0e25c61`부터 `7c7889e`까지 8개 커밋으로 반영했다. 상세 보강은 다음과 같다.

위 변경은 `origin/main` 푸시를 확인했다. 대화 맥락 문서는 이 구현 이력 이후에 추가됐다. 이후 문서 자체의 커밋은 Git 이력에서 확인한다.

기록된 검증은 게이트 CLI 테스트 21개 통과, 원본 실패 50개의 텍스트·해시 대조, 스킬 5개 형식과 당시 로컬 링크 33개·개인 연결 5개 확인이다. 초기 UIbowl MCP 조회와 대표 이미지 3장 관찰도 수행했다. 상세 범위는 [전체 평가](../evals/results/summary.md)와 [게이트 평가](../evals/results/design-gate-summary.md)에 있다. 이 수치는 해당 검사 당시의 기록이며 문서 추가 후 링크 수가 고정됐다는 뜻은 아니다.

실제 제품 앱 구현, 브라우저 렌더 비교, 전체 사용자 흐름·접근성 검증은 이 스킬 제작에서 수행하지 않았다. CLI 테스트의 이미지 바이트는 합성 자료이며 실제 이미지 판독 증거가 아니다. 향후 제품 구현에서 실제 화면·동작·토큰 사용·코드 검사와 게이트 판독을 수행해야 한다.

## 2026-09-06 후속 결정: 맥락 기록을 기본 행동으로

사용자는 이 세션의 대화를 재개 가능한 문서로 남기고 이를 기본 행동으로 정해 달라고 요청했다. 루트 `AGENTS.md`에 맥락 문서 읽기, 작업에 해당하는 스킬 적용, 중요한 요구·결정·교정·검증 결과 기록을 명시했다. 단순 상태 질문은 중복 기록하지 않는다. 이 규칙은 현재 저장소 범위이며 전역 Codex 설정을 변경한 것은 아니다.

앞으로 기준이 바뀌면 날짜별로 요청, 결정과 이유, 바뀐 파일, 검증, 남은 일을 추가한다. 현재 유효한 행동은 `AGENTS.md`와 해당 스킬에 반영하고, 과거 교정과 실패 경위는 이 문서에서 보존한다.

## 2026-09-06 Todo 테스트 피드백

사용자는 실제 Todo 결과의 화면 4장을 제공하고 스킬 개선을 요청했다. 원래 프롬프트는 “내가 지금 스킬을 만들었거든? 테스트로 Todo List 만들어줘 html css 정도면 충분할 듯 지금은. 모바일에서 사용하기 쉬워야 해. 채팅으로도 할 수 있으면 좋겠네 투두 생성을”이었다.

새 명시 기준은 요청 없는 로고 제작 금지, 읽는 글자 최소 14px, CTA와 필터 형태 구분, 텍스트 전용 행동 최소화, 의미 있는 아이콘, 불필요한 문구/배치 제거, 필요 없는 스크롤과 hr형 구분선 제거다. “날짜와 시간도 함께”는 금칙어가 아니라 필요 없는 위치에서 시선을 분산하는 문구의 사례다. 목록과 대화가 서로 공간을 빼앗으면 탭/뷰 분리를 검토하도록 했다. 채팅은 입력창의 모양뿐 아니라 전송·결과·실패·재시도·복귀까지 판단한다.

`todo/`의 소스·토큰·기존 리뷰·게이트 결과를 읽고 저장된 전체 화면 2장을 직접 확인했다. 기존 리뷰는 aligned였으나 실제 gate-result는 경로 오류로 UNVERIFIED였다. 토큰을 쓰고 겹치지 않게 만들었다는 사실을 좋은 구성의 증거로 대신한 판독 누락을 확인했다. 새 규칙 이전에 없는 14px 하한을 당시 명시 요구 위반이었다고 소급해 주장하지 않고, 이번 교정 이후 필수 하한으로 적용한다.

[실제 실패 기록](../evals/results/todo-composition-baseline.md)과 화면/코드 해시를 보존하고 [UI 구성 기준](../skills/reference-to-ui/references/ui-composition.md)을 추가했다. 구현·모바일·토큰·문구·리뷰와 AGENTS 기본 지침에 연결했다. 기존 ORC 50개/RUI 7개를 유지한 채 RUI-08–15를 추가해 catalog v2, 총 65개가 됐다. 이전 버전의 판독을 새 통과로 재사용하지 않는다.

이번 요청은 스킬 개선이므로 todo 제품은 수정하지 않는다. 실패 사례 보존과 새 지침의 평가 결과를 구분하고, 향후 todo 개선은 실제 렌더와 상호작용을 다시 검증해야 한다. [새 기준의 독립 평가](../evals/results/todo-composition-green.md)에 관찰·명세·미실행 범위를 남긴다.

## 2026-09-06 레퍼런스 결합 품질 교정

Todo 피드백을 반영하던 중 사용자는 결과가 레퍼런스와 닮지 않고 품질도 전혀 같지 않으며, 여러 레퍼런스의 좋은 부분을 합쳐 반영해야 한다고 추가로 지적했다. 금지 목록 보강만으로 이 요구를 해결할 수 없으므로 긍정적인 채택 기준과 비교 절차를 추가했다.

[P5](../design/reference-language/round-04/prompt-v5.md)를 최초 배경 입력과 작업 중 추가된 태그/셀렉트/날짜 입력으로 구별해 변경 전에 기록했다. article의 표면은 화면 끝까지, 내용은 기존20px 정렬에 두고 흰색/중립 회색을 교대한다. 정보 태그에 입장 공간·크기와 공식 아이콘을 표시하고 추가 준비물/제한을 보존한다. 셀렉트는 닫힌 필드/화살표/포커스를 공통화하고 OS 옵션 팝업은 그대로다. 마감 날짜는 시각 보조줄을 없애고 disabled와 접근성 마감 이름을 유지한다.

reference-decompose의 요소 상태 계약과 반복 묶음 계약, design-tokens의 상태별 치수 안정성을 보완했다. 교대 배경·태그색·고정px를 보편 규칙으로 만들지 않고, 반복 컨트롤의 상태 추가 내용과 부모 stretch/형제 치수 영향을 확인하도록 했다. 일반 긴 본문·펼침·글자 확대는 내용에 따라 늘어날 수 있고 필수 사유는 삭제하지 않는다. P4 자료와 PASS를 과거 기록에 보존하고 새 사용자 실패를 후속으로 기록한다.

실제390/320에서 카페 교대표면/태그, 첫 예약진입, 날짜7개44px동일/disabled, 셀렉트의 공통외형을 확인했다. 추가 접근성·행동 및 최종게이트 결과는 [P5 평가](../evals/results/reference-controls-p5.md)와 [제품 리뷰](../design/reference-language/round-04/review.md)에 연결한다. 독립 fresh 반복실험의 제한과 네이티브 옵션/실물폰 검증 범위는 별도이며 사용자 품질 승인으로 확대하지 않는다.

후속 셀렉트 검증: 자동화에서 방향키로 OS 팝업 선택 변경은 확인하지 못했으나 네이티브 typeahead(숫자키+Enter)는 실제 인원2→3/반려동물1→2와 focus 유지를 확인했다. 이를 프로그램 `selectOption`이나 팝업 외형 커스텀 검증으로 바꾸어 보고하지 않는다.

추가 사용자 교정: 태그 아래 이동가방 필수가 왼쪽 사진 하단 밖으로 내려왔다. 사진112px 고정/정보128px 불일치를 확인하고, 사진은 최소높이에서 정보행을 채우도록 수정했다. 기본390에서모든매장의사진/정보높이128px일치,문구/기존가로정렬보존을실측했다. 스킬에 정보 추가 후 사진·정보의 상하단 관계와 높이 소유권 재검사를 연결했다.

이어 시간선택이많고너무넓으며넘김가능여부도모르겠다고지적하고가로스크롤/스크롤바숨김을요청했다. 시간라벨14px/짧은버튼/다음항목부분노출로설계하고가상시간을6개로확장해끝항목까지검증한다. 날짜grid는그대로이며시간영역만가로스크롤한다. 모바일스킬에도숨김시넘김단서·터치/키보드도달·확대·선택복귀검증을연결했다.


시간 목록의 첫 구현에서 grid 자동최소폭이 페이지까지 늘어나는 실패를 확인해 트랙/항목 최소폭을 제한했다. 마지막시간을선택한뒤수정/재진입하면선택칩을가로영역안에드러내도록보완했다. insetfocus가청색버튼에묻히는문제는목록/선택시간의흰focus와고대비시스템색으로수정했다. 기본시간폭은부분노출을확대하려고72px로조정했다. catalog 변경 관련기존21unit검사를실제실행해PASS했으며판독기코드는바꾸지않았다. DESIGN.md 생성스킬의잔존14px절대문구도제한예외로동기화했다.

## 2026-09-10 P6 저장 활성 표현과 테마 호버

사용자는 좋아요를 눌러도 활성 표시가 없고 테마에 불필요한 호버가 있다고 지적했다. 실제 재현에서 localStorage=green/aria-pressed=true인데 하트fill=none/먹색이었다. 데이터 검증만으로 실제 활성 표현을 확인했다고 판단한 누락을 보존한다.

[P6](../design/reference-language/round-04/prompt-v6.md) 입력을 고정하고 저장 버튼에만 채운청색하트/낮은대비선택면을 적용했다. hover중/포인터해제/저장해제에서도 표현이 상태와 맞도록 한다. 테마의 hover배경/전환은제거하고 클릭/키보드초점은유지한다. 스킬에 토글 데이터·ARIA·실제fill/color 동시확인과 불필요한 공통hover 전파 확인을 연결했다. 모든테마의hover를보편금지하지않는다.

부모실제검사에서저장on/off fill/ARIA,테마hover전후동일배경/필터동작을확인하고app lint/checkJs를통과했다. 이전0612dd1과P5게이트는별도보존했다. 최종영향검증/게이트와한계는 [리뷰](../design/reference-language/round-04/review.md)에연결한다. 오늘날짜커밋권한을유지하며푸시는요청하지않았다.

후속 요청은 제목의 성수 중복·목록 메뉴 가격 제거와 동반 조건의 명확한 위계였다. 에이전트는 공간 태그를 별도 상위 정보로 나눴으나 사용자는 실내/마당도 같은 동반 조건이라며 거절했다. 중간안의 내부 검증 통과를 제품 품질 승인으로 사용하지 않는다. 거절된 소스/이미지는 `evidence/p6-rejected-information`에 보존한다.

재교정은 이름 아래 가상 카페 소개(14px)를 추가하고 모든 공간/크기/준비물 태그를 하나의 동반 조건 묶음으로 모은다. 지역 한정 홈에서 반복 지역명·목록 메뉴 가격은 제거하고 전체/저장 맥락의 지역 및 상세/예약의 중요 조건·비용은 보존한다. product-reasoning에는 내용의 의미를 먼저 묶고 레퍼런스 메타데이터를 제품의 판단에 맞춰 선택하는 조건부 기준을 추가했다. 실제 완료/검증 범위는 P6 리뷰를 따른다.

320px 기본 첫 예약 버튼이 탭에6px 가려지는 영향도 발견했다. 목록 날짜 아래 여백만12→4px로 줄이고 본문·조건 글자와 섹션 간격은 보존했다. 부모는 최신390/320 목록을 직접 판독했고 보드3폭 동작/이미지/폭/키보드, 앱과 보드 검증 코드 lint/checkJs, 수정 스킬2개 형식과 로컬 문서 링크를 확인했다.
