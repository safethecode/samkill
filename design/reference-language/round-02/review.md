# 디맨드 비교와 교정 기록

현재는 디맨드에 대한 사용자 교정 대기 상태다. 원본과 실제 HTML/CSS 조립 화면을390px 표시 폭으로 나란히 확인했다. [비교 이미지](evidence/assembled-p2.png)는 P2 시점이다. 원본1170px폭의1/3표시이며 원래CSS viewport나DPR를 확인한 것이 아니다.

## 원본에서 유지한 관계

| Q/E | 실제 관찰 | 판단 |
|---|---|---|
| Q1/E1–3 | 연보라배경 위 흰 검색과 작은 필터. 전체만 짙은 배경이고 헤더도구는 흐린 실루엣 | 기본위계 유지. 원본과Lucide의기호세부형태는차이 |
| Q2/E4 | 원형아바타→이름/자격/소속,별도우측찜. 현직파랑/인증보라,붉은채움/회색윤곽 하트 | 소속과상태관계 유지 |
| Q3/E5 | 설명이 카드안왼쪽x32로 돌아옴. footer는 양끝정렬 | 관계유지. 원본과선택서체/14px하한으로세부글자크기·굵기차이 |
| Q4/E4 부분관찰 | 둘째카드의상단과식별정보만재현,키보드뒤문구를생성하지않음 | 관찰범위보존 |

## F1 — 부모 높이와 자식 치수의 모순

내부발견,사용자지적아님. R2/P1/E4의48px부모에 이름24+gap8+메타24=56px을지정했다. 구현담당은세부치를보존하여카드188/둘째y380이됐다. P1자체의수치모순이므로구현담당이원본을잘못봤다는결론은아니다.

[P2](prompt-v2.md)로24+2+22=48을선택해390에서카드180/둘째y372를재검증했다. 좁은320에서는글자줄바꿈에따라높이가늘어나는것을보존했다. 최초프롬프트와 evidence/p1-source 및 screen-p1-390/320.png는보존했다. 스킬의계약에고정박스와자식치수합검산을보완했다.

## F2 — 같은CSS인데 독립 표본의 폭이 달라짐

내부리뷰가발견했다. 독립표본페이지의설명용부모padding24px이390뷰포트의표본을342px로줄여검색폭310px/필터2줄이됐다. 조립화면은검색358px/필터1줄이었다. 동일클래스만확인하고부모의가용폭을빠뜨린구현문맥실패다.

[P3](prompt-v3.md)로설명영역과표본영역의여백소유권을분리한다. 같은폭에서실제박스/줄수를맞추는검증을스킬에추가했다. 다른폭의비교를의도한경우에는조건을표시하는반례를함께남긴다. 초기FAIL과수정후검사는 gate-review.md와failure-events.jsonl에보존한다.

## 입력 격리와 한계

구현담당은 P1/P2/P3 및허용아바타·공식SVG만읽고원본은보지않았다. 원본을본부모와독립리뷰담당의관찰/치수교정은텍스트입력으로전달했다. 최초P1과검토후수정결과의조건을구별하며한번의독립생성으로모든관계가맞았다고하지않는다.

[게이트 리뷰](gate-review.md)는입력편집·삭제/키보드/포커스·폭·글자·시각판독과75개활성규칙을이정적표본범위에서다룬다. 검색API/실제찜/회원흐름/멘토내용의진실성·OS키보드동작은이실험에서구현하거나검증하지않았다. 출처의정지화면을새서비스의사실·효과로옮기지않는다.

## 최종 재검증

[최종 비교](evidence/assembled-final.png)와 요소영역을 직접 확인했다. 배경/흰표면, 아바타와자격·소속, 두찜상태, 설명/상담이력의위계를유지한다. 원본의 작은상담이력글자와 구현14px의 크기·굵기 차이, 공식Lucide 기호의실루엣차이는 남아있다. 픽셀완전일치로보고하지않는다.

비교보드1100/390/320px에서가로넘침과14px미만읽는글자없음, 모든원본/iframe이미지로드,프롬프트열기·닫기,로컬링크HTTP200을확인했다(evidence/board-checks.json). E4/E5의원본대응영역은실제조립컴포넌트를같은폭으로잘라표시하고, 좌표용직접값은비교용크롭에만사용한다. 제품배치나토큰의광학보정으로사용한것이아니다.
