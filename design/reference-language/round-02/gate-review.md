검사자: demand_review. 2026-09-10. 원본 assets/source.png를 직접 열고 P1과 비교했다. 실제 CSS viewport/DPR/서체는 미확인이다. 본 기록의 관찰은 구현 담당의 설명을 재사용한 판정이 아니다. 정적 재현 범위는 OS 상태바/키보드를 제외한 y148–1529 image-px. 입력 타이핑 외 검색/이동/찜 서비스는 요청 범위가 아니다.

## 구현 전 원본 ↔ P1

- V1/E1: 제목 왼쪽, 오른쪽 옅은 채움 알림·하트·인물의 구조가 원본에 보인다. P1 공식 Lucide를 사용하므로 원본 패밀리와 실루엣이 완전히 같지는 않을 수 있다. 원본 도구의 색은 제목보다 매우 옅다. 검정 윤곽선으로 바뀌는 퇴보는 허용하지 않는다.
- V2/E2: 흰 검색 표면, 짙은 회색 윤곽 검색 아이콘, 옅은 안내문, 화면 제목과 검색 사이의 넓은 공백을 관찰했다. 원본 커서는 보이지만 P1 autofocus 생략은 새 구현 선택으로 적절히 분리됐다. 필드 46px와 150ms는 사용자 지정이나 원본 측정 CSS가 아닌 분석자가 고른 수치다.
- V3/E3: 전체만 짙은 남색 채움+흰 글자이며 나머지 3개는 흰 pill+옅은 글자. 작은 내용폭 필터가 카드보다 낮고 좁은 관계가 핵심이다. P1은 이를 담는다. 320 줄바꿈은 새로운 반응형 선택이다.
- V4/E4: 원형 새 아바타, 오른쪽 이름과 소속, 카드 우상단 별도 하트, 첫 카드의 붉은 채움과 둘째의 회색 윤곽이 보인다. 첫 현직은 파랑, 둘째 인증은 보라. P1은 색과 정보 차이를 보존한다. 카드 반경과 2색 배지를 중립화하면 재현 손실이다.
- V5/E5: 설명 시작이 이름 열이 아니라 아바타 왼쪽선으로 돌아온다. 설명 아래 횟수/면접이 좌우 끝을 점유하며 구분선은 없다. 원본 긴 문장은 한 줄이나 P1의 14px 하한과 플랫폼 서체로 줄바꿈이 생길 수 있다. 실제 렌더에서 카드 확장이 다음 카드의 식별 영역까지 가리는지 확인해야 한다.
- V6/E4 두번째: 키보드가 카드의 중간을 가리며 위쪽 양 모서리와 양옆 경계는 보인다. P1은 알려진 식별정보만 재현하며 가려진 설명/횟수는 만들지 않는다. 단일 프레임 crop은 관찰영역 표시 장치이며 실제 앱 스크롤 구현의 증거가 아니다.

현재 P1에서 확정한 번역 누락은 없다. 긴 문장의 줄바꿈과 둘째 카드의 가시성, 상단 filled 아이콘은 첫 렌더에서 우선 판독한다. 구현/시각/행동 게이트는 아직 미실행이다.

## 실제 행동과 코드 근거

네 화면 모두 이미지실패0,문서가로폭=viewport폭,읽는글자/placeholder14px이상(14/18px두단계). 부모/자식의불필요한내부스크롤은없다. ul/li/article/header/footer/input이역할을표현하며정적하트/도구에는접근가능한상태이름이있다. 검색/카드/배지/여백은ui.css의의미변수를실제참조하고미정의/미사용변수는없다. 공식제공SVG와동일path를사용하고상태별fill/stroke만구별한다.

입력은Tab초점→‘셀트리온’입력→전체선택/삭제→80자긴입력→삭제→Enter를실행했다. 입력값을보존/삭제했고Enter는서비스요청이나이동을약속하지않는다. 긴입력과focus전후검색박스의위치·크기불변. focus최종은2px파란inset경계하나이며내부input outline은없다. hover진입60ms에는중간inset색/폭,종료후2px,hover해제60ms에는감소하는중간값을관찰했다. hover로크기/위치를바꾸지않는다. reduced-motion에서는transition:none,forced-colors에서는같은크기의2pxHighlight outline이보존됐다. 실제휴대폰OS키보드·Safari·실서비스검색/로그인/찜/목적지이동은검증범위밖이다. 고대비전체제품적합성/접근성인증으로확대하지않는다.

생성제품은HTML/CSS이며검증용JS의기존anti-slop일반규칙lint와tsc를실행해통과했다. Python helper는동결한사람판독/근거의직렬화도구로자동미관판독이아니다. 이기록과소스를바꾼뒤해시만갱신해과거화면을재사용하면안된다.
