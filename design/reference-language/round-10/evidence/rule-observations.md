# 실제 판정

## ORC-F01 — not-applicable
사이드바가 없는 하객용 세로 청첩장이다.

## ORC-F02 — not-applicable
사이드바가 없으며 주요 행동에는 같은 강조색을 쓴다.

## ORC-F03 — pass
진한 주버튼500/흰글자, 토스트500/흰글자. 사진 위 글자가 없어 사진 대비에 의존하지 않는다.

## ORC-F04 — exception
긴 초대장의 참석 응답을 본문과 빠른 안내에 제공한다. 첫 커버에서는 안내를 숨기고 같은 응답 폼/저장값을 공유한다.

## ORC-F05 — exception
방명록은 이름·작성일·메시지를 읽는 개인 축하글이다. 일반 테이블 대신 문장형 article을 사용하며 최대50개로 제한한다. 계좌4개도 예금주별 접힘 행으로 읽는다.

## ORC-F06 — exception
갈색 계열의 청첩장 강조색을 선택일/실행에 쓴다. 오류는 별도 붉은색+문구이며 금융 위험 상태를 나타내지 않는다.

## ORC-F07 — exception
도구가 아닌 청첩장 표지의 이름32px(320에서28), serif400을 허용한다. 폼제목24/본문16/보조14로 구별했다.

## ORC-F08 — exception
터치 환경에서 축하글 수정/삭제를 숨기지 않는다. 계좌 복사는 대상별로 노출한다. hover 의존 메뉴로 바꾸지 않는다.

## ORC-F09 — not-applicable
높이를 맞출 대시보드 다열이 없다. 사진과 연락처의 소규모 동급 그룹만 있다.

## ORC-F10 — exception
공식아이콘20px/라벨14px/gap4px를 선택했다. +2~4px 규칙의 크기차이만 예외이며 flex중앙/동일색/실제보이는묶음을 확인했다.

## ORC-F11 — pass
SVG currentColor와 상위 버튼색을 공유한다. 호버는 같은 묶음의 배경만 바뀐다.

## ORC-F12 — pass
화면좌우24(320에서20), 내부4/8/12/16/24/32/48/64를 같은 역할에 사용한다.

## ORC-F13 — pass
button/summary와 라디오라벨 cursor pointer, 링크는 기본pointer, disabled not-allowed.

## ORC-F14 — pass
main/section/header/footer/nav/dialog/form/fieldset/table/article/time 사용. div는 행/그리드/약도/사진정렬용이다.

## ORC-F16 — pass
본문은 자연스크롤, 긴모달만 제한높이/스크롤. 방명록·계좌·교통에 내부스크롤이 없다.

## ORC-F15 — pass
항목마다 다른색 배지를 만들지 않았다. 입력선택/오류와 예식일의 역할이 구별된다.

## ORC-G01 — pass
gradient를 사용하지 않는다. 사진 위 어두운 덮개도 추가하지 않았다.

## ORC-G02 — pass
장식 그림자 없음. 경계용inset1/2px만 사용하며 호버 그림자 증가 없음.

## ORC-G03 — exception
모달 외곽12px, 선택일원형, 약도공원곡면은역할별예외다. 반복버튼/필드는6px, 사진은직각이다.

## ORC-G04 — exception
일반UI는갈색강조+중립색, 오류빨강이다. 약도녹색은지리표현으로한정한다.

## ORC-G05 — pass
호버는 배경/색만 변경. 이동·확대·투명도 애니메이션 없음.

## ORC-G06 — exception
32/24/16/14 네 역할은 긴 청첩장 표지·섹션·본문·보조의 위계다. 폼에는24/16/14 세 역할이다.

## ORC-G07 — pass
설명된 간격 토큰과 지도역할 값으로 구별했다. 좌우 컨테이너 기준 공유.

## ORC-G08 — exception
정보밀도형 도구가 아닌 모바일 초대장이다. 사진/인사글의여유와달력/교통/참석의가독성을보존한다.

## ORC-G09 — pass
사진/달력/약도/폼/계좌/글/공유는 사용자정보·행동 역할을 갖는다. 임의마크/장식선이 없다.

## ORC-G10 — not-applicable
사이드바/본문 대비 패턴이 없다. 폼/초대장 톤 비교는 RUI-23에서 수행한다.

## ORC-G11 — pass
진한 표면의 글자흰색/500, 일반본문은 밝은종이면의먹색. 실제표지와폼·하단판독.

## ORC-G12 — exception
긴 본문에서 참석 흐름과 위치에 즉시 접근하기 위한 하단 빠른 안내의 중복에 한정한다. 다른 CTA를 복제하지 않았다.

## ORC-G13 — exception
최대50개 로컬 축하글은 수치 비교가 아닌 문장 읽기다. 메시지 article의 자연 높이를 유지한다.

## ORC-G14 — exception
지도공원의 연한 녹색은 성공상태가 아닌 지리 정보, 갈색은 이 청첩장의 실행/예식일 표시다.

## ORC-G15 — exception
청첩장 표지의 인물 이름만32/28px. 작성 모달 제목은24px이다.

## ORC-G16 — exception
모바일 축하글 CRUD와 계좌 복사만 항목별 행동을 유지한다. 예시의 읽기·수정 접근성을 우선한다.

## ORC-G17 — not-applicable
대시보드 다열 위젯이 없다.

## ORC-G18 — exception
20px 아이콘은14px 라벨보다6px 크다. 모바일 길찾기/복사 식별과48px조작영역을 함께 검증한 이번 청첩장 선택이다.

## ORC-G19 — pass
아이콘이 상위currentColor를 상속하고 라벨과 상태색을 공유한다.

## ORC-G20 — pass
상단/본문/하단의 좌우공통공간과 명확한모달24px컨테이너를 사용한다. 고정안내는 실측높이예약.

## ORC-G21 — pass
실행은button, 이동은a, 접힘은summary로 구현. 비활성은not-allowed.

## ORC-G22 — not-applicable
상태 배지와 entity 색상 체계가 없다.

## ORC-G23 — pass
소규모목록에고정높이가없고 모달만실제긴내용에스크롤. 마지막내용가림320/390확대재확인.

## ORC-G24 — pass
시맨틱구조와DOM비율을검토했다. 날짜달력table, 축하글article/time, 폼fieldset/legend.

## ORC-A01 — pass
사진직각/입력버튼6px/모달12px/달력원형을 구별한다.

## ORC-A02 — pass
종이바탕·중립정보면·참석강조면·실제생성사진으로깊이를나눈다. 전체백색하나로밀지않는다.

## ORC-A03 — exception
box-shadow는 입력·버튼의 일정두께 inset경계에만 쓴다. 장식 그림자나 영역 구분선이 아니다.

## ORC-A04 — pass
사용자가 별도선택없이 완성하라고 명시했다. 사진과청첩장에맞춘갈색계열을 선택했으며blue500없음.

## ORC-A05 — exception
청첩장의 사진·이름·인사는 중앙대칭을 채택한다. 교통·계좌·입력·축하글은 읽기 중심 왼쪽정렬이다.

## ORC-A06 — exception
하객용 청첩장에 상품가격/평점/판매자나 대시보드밀도를 강제하지 않는다. 첫viewport에이름·사진·예식일시가 읽힌다.

## ORC-A07 — exception
닫기와 인원 +/-만 icon-only다. 접근 가능한 이름·44/48px 영역·키보드초점을 유지한다.

## ORC-A08 — pass
가상두사람의전신/근접사진을생성해포함했다. 비율·crop·인물표현을실제판독하고 placeholder없음.

## ORC-A09 — pass
사진2장그리드외인사/달력/교통/참석/계좌/글이동일카드반복이아니다.

## ORC-A10 — exception
동기 로컬저장에는 가짜 skeleton/네트워크로딩을 추가하지 않는다. 빈글/저장오류/손상값보호/복사실패복구/취소를 실행했다. 계좌·연락·실제서버는예시범위로명시한다.

## RUI-01 — pass
출처화면390과추정시각값/제품chosen CSS를 reference-brief에구분했다. 정지화면을고정동작으로오인하지않는다.

## RUI-02 — pass
style.css토큰의실제사용과역할별직접값을DESIGN에기록했다. 약도/모달/사진치수는별도선택이다.

## RUI-03 — pass
catalog5의75개활성규칙을전부판정하고예외/미적용을유지한다. CLI무결성과실제판독을구별한다.

## RUI-04 — pass
갤러리/ICS/지도경로/복사/로컬참석CRUD/축하글CRUD/마무리링크를실행했다. 실제응답서버·연락처·송금·배포는예시범위명시.

## RUI-05 — pass
기성청첩장흐름에자동팝업제거·안정된빠른안내·초점복귀·예시경계·상태보존을결합했다.

## RUI-06 — pass
소유app/icons/build의checkJs와anti-slop전체일반규칙lint통과. 의존번들을소유소스로세지않는다.

## RUI-07 — pass
첫사진/이름/일시, 인사→실용정보→참석, 대상별계좌/글, 마지막공유를구현전계약에연결했다.

## RUI-08 — pass
제품명/로고/브랜드마크를만들지않았다. 두사람이름과청첩장섹션문구만작성했다.

## RUI-09 — pass
모든읽는본문/라벨/버튼/보조14px이상. computed최소값과200%글자를확인했다.

## RUI-10 — pass
실행은표면/경계버튼. 지도/앵커는목적지, 라디오는선택, 참석은제출로구별한다.

## RUI-11 — pass
예시범위안내는해당전송/계좌/장소·저장근처에둔다. 실제결과를오인시키지않는필요조건이다.

## RUI-12 — pass
공식LucideSVG출처/라이선스포함. 지도/복사/연락/공유/닫기/인원아이콘의의미와accessible name확인.

## RUI-13 — pass
본문/방명록은자연높이, 고정안내높이실측으로끝내용가림방지. 약도200%겹침발견후rem공간과외부설명으로수정.

## RUI-14 — pass
hr/영역border/밑줄/gradient없음. forced-colors내비외곽선도제거. 입력경계/초점과약도의도로데이터만존재.

## RUI-15 — not-applicable
채팅 요청/대화 흐름이 없다. 축하글은 로컬 방명록 CRUD다.

## RUI-16 — pass
Q1~4의원본사진/인사/교통·폼/마무리와first-cover/최종표면을동일390폭으로직접대조했다.

## RUI-17 — pass
사진축소/글겹침없는첫화면과중앙인사리듬, 실용폼을공통종이면/갈색체계로유지. 확대약도퇴보를수정후직접판독.

## RUI-18 — pass

## RUI-19 — not-applicable
목적지 탭바가 아니다. 하단은 위치 앵커+참석 실행의 빠른 안내다.

## RUI-20 — pass
참석응답/축하글생성수정/연락처는별도주제목24와본문16/보조14를갖는다.

## RUI-21 — not-applicable

## RUI-22 — pass

## RUI-24 — pass
커버의일시는초대식별, 일정영역달력은일정저장맥락. 한묶음안의중복제목/배지를추가하지않고인원에본인포함조건유지.
