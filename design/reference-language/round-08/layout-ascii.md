# 구현 전 구조 · P1

R1 원본 / 요리 상세             → D1 제품 / 요리 상세
상단 사진 [뒤로 | 저장]           → 음식 사진 [뒤로]
사진 하단 요리명 2줄             → 요리명 1~2줄
출처 / Cook 행동들               → 가진 재료로 가능한 정도 / 요리 시작
설명 / 난이도·조리·전체 시간       → 시간·인분 / 요리 설명
재료 제목 / 인분 / 목록           → 재료 제목 / 보유·부족 목록

원본 fixed/scroll은 정지 이미지로 미확인. 제품은 본문 단일 스크롤,상단 뒤로는 사진 안,CTA는 정보 다음의 문서흐름. 하단 탭은 상세에서 숨겨 화면 경쟁 제거.

R3 원본 / 재료                   → D3 제품 / 내 냉장고
제목 / 설정                      → 제목 / 사진 등록
종류 이미지·이름 — 수량·이동       → 재료 이름·수량 — 선택 체크
반복 카테고리 목록                → 종류 필터 후 재료 목록
재료추가 / 광고 / 하단탭           → 선택한 재료로 요리보기 / 하단 목적지

광고 제외,재료 수량/선택 상태는 실제 목록과 연결. 등록은 화면 전체 대상,선택해서 요리보기는 선택 집합 대상. CTA와 필터 표현을 분리한다.

R4 촬영                          → D4 사진 등록
닫기 / 안내                      → 뒤로 / 촬영 목적
카메라 프리뷰+바코드 프레임         → 실제 프리뷰 / 사진 촬영
                                 → 앨범에서 선택 / 직접 재료 선택
사진 이후 원본 미확인              → 사진 확인 + 재료 체크 → 등록

R2 조리                          → D2 조리
요리명 / 닫기                    → 요리명 / 닫기
현재 단계 밝은표면 / 다음 어두운면   → 현재 단계 큰 문장 + 단계번호
하단 재료 등                     → 이전 / 다음 / 마지막 완료

비교 질문: 사진을 작게 압축하지 않았는가,제목이 사진보다 먼저 과장되지 않았는가,메타와 주행동이 같은 회색칩으로 섞이지 않는가,재료 선택을 위해 전체 사진을 지나 스크롤해야 하지는 않는가. 홈에서는 재료 요약을 사진 위에 두어 마지막 문제를 피한다.

## 사용자 교정 P4: 냉장고 행동 위치 (구현 전)

기존: 헤더 → 필터 → 제목 / 개수 → 가변 목록 → 추가 → 요리 보기 → 고정 탭.
변경: 헤더 → 스크롤 영역[필터 → 제목+개수 태그 / 재료 추가+ → 목록] → 고정 영역[전체 선택 재료로 요리 보기 → 탭].
요리 보기는 현재 필터와 무관한 전체 선택 집합에 적용한다. 항목 수가 바뀌어도 행동의 높이는 유지한다. 목록 마지막 항목은 고정 영역에 가려지지 않아야 한다. 재료 추가는 목록 도구로 배치하며 오른쪽 플러스는 사용자의 명시 요청이다. 개수 태그는 현재 필터 결과 수다.
