# Round8 최종 검토

2026-09-11. 범위는 로컬 냉장고·요리 선택 프로토타입이다. 75개 활성 공통 규칙과 3개 프로젝트 완료 조건을 각각 판독했다. 전체화면/다른 앱 캡처는 사용하지 않았고, 이 앱의 HTTP·직접 파일 진입과 저장된 레퍼런스만 확인했다. 게이트 상태는 `gate-result.json`의 실제 CLI 결과를 기준으로 한다.

## 제품과 시각 판정

Q1–Q5는 아래 확인 범위에서 `adapted-and-verified`다. CREME와 같은 음식·서체·배경 영상까지 재현했다는 뜻이 아니다. 원본의 영상 배경 몰입감과 여러 보조 기능은 구현과 다르며, 이 앱은 가진 재료로 한 끼를 선택하는 과제를 우선한다. 사용자의 품질 승인, 실제 기기 시험, 서비스 출시 가능 여부는 내부 검토에 포함하지 않는다.

| 관계 | 직접 비교와 판정 |
|---|---|
| Q1 상세 | [390px 비교](evidence/compare-detail.png). 상부 음식 식별 사진, 흰 굵은 제목, 짧은 정보, 산호색 실행, 아래 재료의 읽는 순서를 유지했다. 사진330px는 첫300px보다 비중을 늘린 결과다. 원본은 사진/제목이 겹치고 이 앱은 사진 뒤 제목을 분리한다. 좁은폭에서 제목 대비를 유지하면서 음식 식별과 주행동을 찾을 수 있다. 원본과 같은 몰입감이라고 판정하지 않는다. |
| Q2 조리 | [390px 비교](evidence/compare-cook.png). 최초 조리 UI에서는 완성 사진이 안내보다 먼저220px를 차지했다. 이번 직접 비교에서 현재 단계가 밀린 것을 퇴보로 판단해 사진을 제거하고, 현재24px/밝은면과 다른 단계16px/중립면의 순서 목록으로 바꿨다. 다음·이전·완료 및 키보드 진행을 실행했다. 원본의 영상·AI 도움말은 제공하지 않는다. |

| Q4 촬영 | [허가 전 비교](evidence/compare-camera.png), [합성 장치 프리뷰](evidence/latest-live-camera.png). 큰 프리뷰와 상단 닫기 관계를 가져왔다. 실제 식재료 사진은 좁은 바코드 프레임에 맞출 이유가 없어 그 프레임은 제외했다. 카메라 허가 전에는 준비 면을 보이고 촬영 성공처럼 꾸미지 않는다. 합성 장치는 영상 연결·촬영 동작의 브라우저 증거이며 실제 스마트폰 카메라 화질/OS 경험 검증이 아니다. |

원본PNG의 실제 CSS viewport와 DPR는 미상이다. 비교보드는 원본과 구현의 표시 폭만390px로 맞췄다. 스크린샷에 보이는 수치를 원본 CSS 실측값으로 부르지 않는다. `compare-*.html`로 비교를 다시 열 수 있다.

## 제한한 예외와 미적용

`gate-contract.json`에 원문 임계값과 충돌하는 적용 범위를 ID별로 기록했다. 주요 예외는 R1/R2에서 채택한14/20px 반경, 사용자의 산호색 실행/선택 방향, 명시한 카메라·plus 단독 버튼, 터치/키보드에 필요한 항상 보이는 checkbox,4px 버튼 간격과 세로형22px 탭 아이콘, 단일 본문 스크롤과 레이아웃을 흔들지 않는 inset 초점/선택 경계다. 이는 모든 UI에 같은 예외를 허용하는 기준이 아니다.

사이드바/다열 대시보드/20개 이상 표형 데이터/채팅/날짜picker는 이 제품에 없어 해당 규칙만 미적용이다. 미구현 자동인식·인증·동기화·공개배포를 기존75개 규칙의 미적용 이유로 돌리지 않았다. 오류/빈 상태에 그림이나 가짜 skeleton을 강제하지 않고 실제 대기와 복구를 표현한 차이는 별도 예외로 남겼다.

실제 스마트폰/OS 앨범/실물 카메라, 원본의 정확한 서체·모션, 음식사진의 공개 재사용 허가, 서버 자동인식은 검증하거나 제공하지 않았다. 이 로컬 실험의 게이트 결과를 해당 범위까지 확대하지 않는다.
