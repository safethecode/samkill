# Round 8 · 냉장고 재료로 한 끼 고르기

## 제품과 범위
냉장고 앞에서 가진 재료를 확인하고 요리를 고르는 사람을 위한 로컬 모바일 웹 프로토타입이다. 재료 선택 → 요리 목록 → 재료 상세 → 조리 순서를 연결한다. 사진은 카메라/앨범에서 실제 선택하고 미리 본 뒤 사용자가 재료를 직접 확인해 등록한다. 자동 이미지 인식은 연결하지 않으며 인식 성공을 연출하지 않는다. 예시 재료와 레시피임을 첫 화면에 표시한다. 서버·인증·배포는 이번 실험 범위가 아니다.

## 근거와 시각 방향
- R1: CREME 요리 상세. 어두운 전체 바탕, 화면 상부를 크게 차지하는 음식 사진, 흰색 굵은 2줄 요리명, 작은 산호색 조리 행동, 짧은 조리 정보, 아래의 재료 목록을 직접 관찰했다.
- R2: CREME 조리 순서. 어두운 화면 안에서 현재 단계만 밝은 중립 표면으로 구분하며 문장을 큰 글자로 읽게 한다.
- R3: 냉장고털기 카테고리별 재료. 왼쪽 재료 표현/이름과 오른쪽 보유량을 같은 행으로 연결한다. 요리에 쓸 재료를 고르는 본 제품에서는 수량 대신 체크를 오른쪽에 둔다.
- R4: 메디코치 촬영. 화면 대부분을 카메라 프리뷰로 쓰고 상단 안내와 닫기를 분리한다. 바코드용 프레임은 식재료 전체 사진에 부적합하여 제외한다.

원본은 references의 PNG이며 원본 CSS/DPR는 미상이다. 관찰값은 image-px 추정, 아래 값은 CSS-px chosen이다. 390/320 폭, 844/740 높이와 200% 글자로 검증한다.

토큰은 dist/tokens.css에 기본값→역할→사용처를 연결한다. 화면 바탕 #111111, 표면 #212121, 글자 #ffffff, 보조 #d1d5db, 경계 #656565. 원본의 어두운 대비와 제한된 강조색을 유지하기 위한 chosen 값이며 공식 CREME 토큰이 아니다. 모든 화면의 .inset이 좌우20px를 소유한다. 기본 모션160ms ease-out,동작줄이기0ms. 공식 Lucide SVG만 사용한다. 사진 crop/프리뷰 비율/100%/0값은 콘텐츠와 레이아웃 직접값 예외다.

## Q-ID와 첫 비교
Q1 R1→요리 상세: 큰 사진/흰 제목/짧은 메타/재료의 순서와 면적 관계. 실제 앱 detail 상태를 먼저 렌더하고 같은390px 표시폭으로 비교한다.
Q2 R2→조리: 현재 단계 강조와 큰 문장,단계 전환 후 기존 입력/선택 보존.
Q3 R3→냉장고: 재료명/수량 또는 선택의 행내 관계,종류별 목록과 등록 동작 구별.
Q4 R4→사진: 프리뷰 중심,촬영 시작과 등록 확정 분리,권한거절 복구.
Q5 전체 조합: 동일 바탕·제목·간격·실행색,사진의 자연색을 제품 전체 팔레트로 확대하지 않음.

Do: 음식 사진의 비중,실제 선택에 필요한 보유/부족 재료,읽는 순서를 보존한다.
Avoid: 임의 로고/슬로건/녹색 팔레트/전체 무채색 미니멀화/색만 맞춘 완료/구분선/탭밑줄/가짜 AI 인식/광고/가짜 평점.
차이: 흰 재료 관리 레퍼런스는 R1의 어두운 공통 시스템에 통합한다. 재료 목록의 관계만 가져오는 보조 출처임을 명시한다. 실제 앱 사진은 별도 출처 에셋이며 원본 음식 이미지를 추출해 쓰지 않는다.
Unknown: 실제 스마트폰 카메라·OS앨범 UI,사진 자동인식,원본 모션과 정확한 서체. 로컬 브라우저에서 가능한 검증은 별도로 수행한다.

## 피드백
F8-01 사용자: 기존 창작에서 색·배치가 이상하거나 지나치게 단순해 원본 느낌이 사라짐. Q1–Q5와 첫 비교에 연결한다. 최종 사용자의 품질 승인은 내부 검증과 구별한다.
F8-02 사용자: 반복 지적을 스킬에 녹일 것. 사례별 변경값은 여기,원인·적용조건·반례·평가는 관리 원본 skills에 남긴다. 기존 피드백 절차를 재사용하고 실제로 드러난 누락만 보완한다.

## P4 사용자 교정: 냉장고 목록과 행동

요리 보기 CTA는 전체 선택 집합에 적용하므로 목록 길이/필터에 따라 움직이지 않도록 탭 위의 독립 하단 영역에 둔다. 목록은 남은 공간에서 스크롤하고 고정 영역과 겹치지 않는다. 현재 필터 이름과 결과 개수 태그를 묶고 오른쪽에 추가 행동을 둔다. 후속 명시 요구에 따라 재료 추가 글자는 생략하고 플러스 아이콘만 표시하며 접근 가능한 이름은 유지한다. 좁은 폭의 확대에서는 도구가 다음 줄로 흐른다. 상단 사진 등록은 카메라 아이콘만 표시하되 48px 터치 영역과 접근 가능한 이름을 보존한다. 모든 행동 버튼을 아이콘으로 축약하는 일반 규칙은 아니다.

320·390 폭, 기본/200% 글자에서 4종 필터의 CTA 위치 유지·마지막 행 접근·추가 화면 이동을 확인했다. evidence/dock-results.json과 dock 스크린샷 참조. 전체 제품 디자인 게이트 완료로 확대하지 않는다.


## 최종 검수 교정과 토큰 범위

일반 버튼 아이콘20px(16px 글자보다4px 큼), 시간 메타18px(14px 글자보다4px 큼), 하단 탐색22px를 역할별로 둔다. 사용자 간격 요구4px는 버튼에만 적용한다. 기본 읽는 글자는14/16/24px 세 크기로 통합했고 굵기와 간격으로 섹션 위계를 보존한다. 부족한 재료와 조리 진행 수치는 중립 글자, 실행/선택만 산호색으로 구별한다. 상세의 인분은 재료 제목 옆 한 번만 표시한다.

프레임·이미지·행·빈 상태·터치·아이콘·초점 두께 등 반복 치수는 tokens.css의 역할 변수로 연결했다. CSS의0/100%/1fr/auto/none/flex 비율과 line-height,50% 중앙 위치·translateX(-50%)은 레이아웃 구조의 직접값이다. 1.25 제목·1.4 섹션·1.45 보조·1.5 본문 줄높이는 해당 역할의 비율 예외이며 픽셀 토큰이 아니다. CSS의330px 중복 직접 덮어쓰기는 역할 변수로 교체했다. 선언만 한 display 토큰은 제거했다.

키보드 필터/체크 및 조리 단계 갱신 뒤 조작 초점을 보존한다. 카메라 연결 중에는 중복 요청을 막고 상태를 표시하며, 대기 중 취소 후 늦게 도착한 스트림도 종료한다. 사진 디코딩 대기·잘못된 형식·읽기 실패의 상태를 실제 복구 경로와 연결한다. 인식 모델은 여전히 미연결이며 이 제한을 성공으로 표시하지 않는다.

원본의 둥근 버튼/사진면을 채택한14/20px 반경, 사용자 명시 아이콘 전용 촬영/추가 및 관례상 뒤로/닫기, 단일 주콘텐츠 스크롤, 접근 가능한 선택/초점을 위한 inset 경계는 게이트에서 정확한 범위의 예외로 기록한다. 색·반경만으로 원본과 동일한 품질을 주장하지 않는다.

Q2 최종 비교에서 완성사진이 조리 안내보다 먼저220px를 점유한 퇴보를 발견했다. 조리 화면에서는 사진을 빼고 전체 단계 목록 중 현재만24px/밝은 면, 다른 단계는16px/중립 면으로 읽게 수정했다. 이전·다음은 하단 sticky 영역이며 마지막 단계·확대에서 현재 안내와 행동 접근을 함께 검사한다. 상세/완료의 음식 식별 사진은 유지한다.
