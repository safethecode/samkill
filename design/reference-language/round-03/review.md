# 닥터다이어리 비교와 교정 기록

사용자는 디맨드 결과를 긍정 평가하고 이번 실험을 요청했다. 닥터다이어리 결과에 대한 사용자 평가는 아직 대기다. 아래 차이는 모두 내부 분석/독립 리뷰에서 발견했다. 원본을 본 분석자와 리뷰어, P1~P4와 지정 에셋만 받은 구현 담당을 구별한다. 구현 담당은 원본 미열람 상태를 유지했다.

## 원본과 결과를 비교하는 범위

Q1 상단의 선택/비선택과 우측 도구, Q2 가로 광고의 큰 박스, Q3 두 열 요약, Q4 네 열·두 행의 바로가기와 그림/라벨 위계, Q5 챌린지 제목/참가 수/보상/그림, Q6 날짜별 기록, Q7 기록에 속한 추가 표시, Q8 다섯 목적지와 하단 가림을 나란히 판독한다. [비교 페이지](index.html)의 원본 영역과 E1~E8 구현은 같은 표시 폭이다. [원본/조립 캡처](evidence/assembled-final.png)와 [개별 표본](components.html)을 함께 제공한다.

원본 CSS/DPR/폰트는 미상이다. 고유 에셋을 사용한 만큼 사진/그림 자체를 언어로 새로 재현한 평가가 아니다. 앱 라벨·정보·컨테이너·배치·탐색을 코드로 재현한 실험이다. 원본 세로선 생략,14px 하한, 표준Lucide 도구의 미세 모양, 밝기/곡률 추정, E5 자연높이는 공개 차이로 남긴다. 앱 탐색·기록 저장·광고 실행은 범위 밖이다.

## 재사용 기준과 사례의 경계

이번 P2/P3는 기존의 잉크/박스 구별, 보이는 가림 관계, 토큰 사용, 의미 구조 기준을 실행에 적용한 교정이다. 새 공통 금지 규칙을 추가하지 않았다. P4의 슬롯/이미지 크기 구별은 [요소 상세 분석](../../../skills/uibowl-research/references/component-anatomy.md)의 박스와 실제 시각 크기를 구별하는 원리를 이번 그림에 적용했다. 원본의 고유 치수/색을 전역 프리셋으로 만들지 않는다.

회귀 후보: 동일 슬롯에 비율/여백이 다른 이미지, 부분 가림 숫자, 설명 heading 배열에 공유 계약이 먼저 나오는 입력. 반례는 원본 자체에서 그림 크기를 통일한 경우, 값 전체가 실제로 가려진 경우, 서로 다른 폭을 의도한 비교다. 이번 사례만으로 새 지침의 범용 정확도 향상을 주장하지 않는다.

최종 항목별 판독·증거·한계는 [게이트 리뷰](gate-review.md), 보드의 좁은 폭에서는14px 라벨로 늘어나는 표본을 위해 iframe 높이를 추가 예약했다. 제품 내부에 새 스크롤 영역을 만든 것이 아니다. 자동화된 무결성 결과는 [gate-result.json](gate-result.json)에 둔다. 게이트는 사람의 판독 기록과 증거 무결성을 검사하며 자동 미관 판별이 아니다.

최종 실행: 활성75개+프로젝트4개 게이트PASS(통과29/명시예외28/미적용22). 보드1100/390/320의8개프롬프트,키보드펼침닫힘/고대비포커스,모든iframe의가로·세로넘침/이미지오류를확인했다. 현재연결175개누락0,검증JS lint/checkJs통과. 이수치는정적재현범위이며위의미확인기능을포함하지않는다.

커밋 공백 검사에서 CSS/기록 스크립트의 행끝 공백을 정리했다. v3/v4 CSS 보관본도 같은 형식 정리를 적용했으며, 최초 의미 내용과 각 시점 렌더는 유지한다. 최종 소스는 이 정리 후 재캡처/게이트 무결성을 다시 확인한다.
