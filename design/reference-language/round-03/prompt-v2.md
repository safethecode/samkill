# P2 · 날짜 행과 부분 가림의 기준점

P1과 동일한 입력/에셋/원본 미공개 조건을 유지한다. 아래에만 우선 적용한다. P1/첫 코드·렌더를 보존한 뒤 수정한다. 원본을 본 분석자의 내부 교정이며 사용자 지적을 받았다는 뜻이 아니다.

## F1 · E6 날짜의 잉크 위치와 행 박스 구별

원본 첫 기록 표면의 위 경계는 약1903 image-px, 선택한 비교 조건에서는(1903-170)×390/1125=600.77 CSS px다. P1 구현에서는614.625px가 되어 약14px 내려갔다. 날짜 글자 잉크의 위치를 행 전체 top처럼 해석해 중복 여백을 줬다.

E5 끝부터 E6 date-row top까지16px, date-row h22, date-row 끝부터 record-list까지10px로 바꾼다.390에서 E5 끝552.625→날짜568.625→첫 기록600.625가 목표다. 날짜 글자 line-height22px와 행 높이를 맞춰 잉크 위치도 함께 대조한다.320에서는 날짜/챌린지의 자연높이를 유지한다. 글자 크기를 줄이지 않는다.

## F2 · E6/E7 부분 숫자의 가림

원본 첫 기록의 선행 `5`는 버튼 왼쪽 위 곡선 밖으로 일부 보인다. P1은 숫자 하나를 오른쪽 끝에 정렬해 완전히 가렸다. 숨은 뒷숫자를 만들지 않는다. 첫 행 record-value에만 폭40px, 텍스트 왼쪽 정렬을 선택해390에서 x317 부근에5를 둔다. 다른 행 값은 기존 오른쪽 정렬 그대로.

FAB는 기록영역 기준 top54px(390 y622.625), right17px,58px 원형. 첫 행 아래까지 걸치는 관계를 보존한다. 기록값의 일부가 보이는지 실제 렌더로 확인한다. E8은 기록영역 기준 top132px(390 y700.625), 나머지64px capsule 유지. 큰글자/320에서 날짜 높이가 늘면 그 증가도 FAB/nav 기준에 반영해 첫/둘째 행과의 관계를 유지한다.

## F3 · E8 아래 남는 기록의 표현

원본 세번째 기록은 탐색 아래에서 매우 옅게 일부 보인다. 조립의 세번째 행만 opacity .16의 선택값으로 옮기고 현재 비교 프레임 아래 가림을 유지한다. 이 선택을 원본 앱의 실제 opacity/fixed 구현이라고 부르지 않는다. 독립 E6도 동일 행 상태를 사용한다. 기록 자체를 삭제하거나 빈 값으로 바꾸지 않는다.

## 입력 정합성과 표본

P1 마지막 조립 문장 E1→E2(12px)는 E1 h64/E2 y64와 모순이다. 괄호12는 삭제하며 E1 끝에 바로 E2를 둔 실제 좌표를 유지한다. E5 min-height100/내용102의 차이는 사전에 자연높이를 허용했던 선택으로 유지하고102px 실측을 기록한다.

components.html에서 #E1~#E8의 제목·프롬프트·실제 표본이 같은E-ID인지 확인한다. 공유 계약은 요소 배열의 한 칸으로 세지 않는다. 자체수정 전의 밀린 매핑은 evidence/p1-source에 보존한다. 같은320폭 표본은 브라우저 전체가 넓어도 내부320 조건이 적용돼야 한다. 미디어쿼리만으로 외부 viewport를 판단하지 말고 표본 컨테이너 기준이나 같은폭 iframe을 사용한다. 표본은 설명 padding 영향을 받지 않는다.

P2를 독립 요소의 수정 설명에 연결하고 P1 원문은 유지한다. .specimen 클래스와 E-ID가 정확하게 유지되도록 검증한다.
