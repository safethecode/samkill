# Round9 이력서 작성·관리 웹

## 과제와 범위
사용자는 지원할 직무에 맞춰 이력서를 작성하고 여러 버전을 관리한다. 실험용 로컬 웹으로 기본 정보·소개·경력·학력·스킬 편집, 이력서별 복제/보관, 명시적 버전 저장/복원, 인쇄/백업을 제공한다. 서버 계정 동기화·실제 채용 제출은 범위 밖이다. 목록에 이 브라우저 저장임을 표시한다. Round8과 별개 제품이다.

## 레퍼런스 관찰 및 채택
- R1 점핏 이력서 목록: 옅은 중립 페이지 안에 흰 콘텐츠 영역, 제목과 생성 행동, 문서 타일. 원본 references/R1-list.png. 목록 Q1에 문서 썸네일과 제목/상태/수정일/관리 행동을 결합한다.
- R2 원티드 이력서 편집: 넓은 중립 작업 바탕, 중앙 흰 문서, 이름·연락처·소개·경력·학력 순서, 상단 저장/미리보기 행동. references/R2-editor.png, R3-editor-detail.png. Q2 문서 영역을 큰 카드들의 나열로 분할하지 않고 여백과 제목으로 구분한다.
- 원본의 얇은 분리선은 사용자 금지에 따라 사용하지 않는다. 원본의 매우 흐린 회색 문구는 읽을 수 있는 대비로 올린다. 원본 px는 이미지 치수이며 DPR/CSS 값은 unknown이다.

## 선택한 값과 요소 계약
값은 chosen이며 기존 브랜드 공식값 주장이 아니다. 페이지 #f5f6f8, 문서/입력 흰색, 본문 #20252d, 보조 #606873, 실행 #1765e8(원티드의 파란 행동 관찰에서 채택), 보조 조작 #eceff3. 서체 시스템 한글 고딕. 본문16/보조14/섹션20/페이지32. 기본 버튼 높이44, 간격4, 모서리8. 페이지 최대1160, 좌우32(좁은 폭20), 목록 문서간24. 사방 여백은 토큰 참조.

E1 목록 제목+생성: 페이지 과제/문서 생성, 좌제목 우주CTA. E2 문서 타일: 종이 미리보기, 제목/직무, 상태와 수정일, 편집/복제/보관. E3 필터/검색: 문서 목록에 소속, 생성과 강조 차등. E4 편집 상단: 목록 복귀/문서명/저장상태/버전저장/미리보기. E5 문서: 기본정보/소개/경력/학력/스킬을 입력하되 결과 문서와 읽기 순서 일치. E6 섹션 탐색: 좌측 보조 탐색, 배경 선택 표시와 no underline. E7 버전: 이름·저장일·복원, 복원 전에 현재 내용을 자동 안전 버전으로 보존. E8 인쇄: 원문 내용이 출력되며 편집 도구는 제외.

아이콘은 공식 Lucide SVG를 동기 인라인 사용. 액션/복제 식별은 선행, 다음 이동은 후행. 모호한 행동은 텍스트 라벨 유지. 포커스는 outline로 외형 위치를 유지하고 reduced motion을 존중한다. 모든 입력에는 연결된 label.

## Q별 비교와 검증
Q1 목록 R1: 문서 면적과 타일 위계·제목/행동 관계. Q2 편집 R2: 중앙 종이, 내용 순서, 각 섹션의 밀도. Q3 목록/편집/미리보기의 글자·입력·행동 톤. Q4 상태: 빈검색·보관·새문서·저장실패·버전복원. Q5 file/HTTP 직접진입 및 1440/1024/390/320, 200%·키보드·인쇄. 실제 비교와 행동검증 전에는 PASS라 하지 않는다.

## 최종 교정과 직접값 범위

- 목록 페이지제목24px/행48px, 본문16·보조14의 세 역할. 문서 섹션 제목은16px 굵기로 섹션 간48px와 결합해 판단한다. 대화상자 주제목24px, editor 상단 문서 제목24px. 그림자 제거, 상태는 중립 회색, 일반 아이콘18px와14px버튼의 조합. 초기에 사용한32px제목/파란완료배지/20px아이콘은 검수 후 교정했다.
- 날짜는 브라우저 month UI 대신 한국어 연월 선택 대화상자로 구현. 적용/취소/해제·포커스·저장값을 검증한다.
- 버전 비교는 변경된 섹션만 우선 표시하며 전체 내용 보기는 별도 선택이다. 제목/섹션 단위 비교이며 단어 단위 diff나 AI 의미비교라고 주장하지 않는다.
- 색/간격/글자/배경/반경/속도는 CSS root 토큰→사용처. 직접값 예외는 화면 최대폭(1224/1256/900), 문서/썸네일의 매체 치수(840·228·290 등), 브레이크포인트(1050/700), 44px조작높이, 48px제목행, 2px포커스와3pxoutline offset, print의A4/mm/pt, 접근성 강제색(system colors), 100%·0·flex/grid구조 값이다. 장식 분리선은 없다.
- 인쇄는 화면과 별도 매체: A4에16mm 여백, 이름24pt, 섹션14pt, 본문11pt·연락처10pt. RUI09는 화면 글자 기준이며 인쇄의 물리 단위와 혼동하지 않는다.
- 모든 문서는 동등한 관리 대상이므로 썸네일 크기를 임의로 다르게 하지 않는다(A09). 카드는 실제 내용 미리보기를 식별 근거로 쓰며 대량 표 데이터가 아니라 개인별 소수 이력서 관리가 현재 핵심 범위(F05/G13). 반복된 보조 행동은 터치/키보드에서 항상 찾을 수 있게 유지한다(F08/G16의hover-only 요구와 접근성 충돌).
- 순수 흰문서/중립작업면은 원티드의 문서 식별을 보존한다(A02 장식추가와 충돌). accent 방향은 원티드 파랑/서핏의 다양한 프로필색/refresh의 중립 대비를 검토하고 작업 행동을 찾기 쉬운 제한적 원티드 파랑을 채택했다(A04). 다른 제품의 브랜드 전체를 복제하지 않는다.
- 제외: 브랜드 로고/슬로건, 채용 확률·허구의 AI 분석, 장식 구분선·탭 밑줄, 무근거 색확장, 실제 서버 저장처럼 표현하기. 키보드·고대비는 유지한다.

## 랜딩페이지 추가

사용자가 랜딩페이지를 추가 요청했다. [랜딩 계약](landing-contract.md)에 구현 전구조·기존refresh/서핏원본과차이·문구와진입행동을기록했다. index는소개,workspace는기존앱. 기존origin/storage키를유지한다. 랜딩은기존파랑/중립팔레트에소개용64/32/16/14px(모바일40/28/16/14)타이포를사용한다. 도구화면24px/세크기기준의예외는소개페이지에한정한다. 실제지원성과/AI평가/사용자후기/기업로고를추가하지않는다. 첫/마지막작성CTA는긴소개를읽는전후의진입점이며도구내중복행동의예외로확대하지않는다. 문서예시는개인저장값을읽지않는공개예시다.

landing.css의root토큰으로컬러/간격/역할크기를정의한다. 직접값예외는1280최대폭,1100/740브레이크포인트,문서demo최소352px,hero여백64/96,미디어비율/0/100%,포커스치수및행간이다. HTML문구의원본은서비스의실제기능이며네이티브details/summary는FAQ의접근가능한펼침동작을제공한다.
