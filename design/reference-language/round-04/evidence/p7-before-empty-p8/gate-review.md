# P6 디자인 게이트 판독

2026-09-10. P6는 저장 상태/테마 hover와 순차 추가된 목록 정보구조의 후속검증이다. 아래 P5의 다른85개 기준/근거는 변경 영향이 없는 범위에서 재사용하며 P6 전체새회귀라고 주장하지 않는다. P5 당시자료는 `evidence/p5-before-save-theme-p6/`에 커밋0612dd1의11파일로 보존했다.

P5 기준 판독: 로컬 Chrome의 390/320 카페 탐색·예약 체험과 비교 보드를 검토한다. 이전 P4 판독은 [당시 사본](evidence/p4-before-row-surfaces/gate-review.md)에 보존했다. 현재 P5의 최종 증거는 `evidence/review-p5/`에 둔다. 원본 CSS viewport/DPR와 제작자의 실제 의도는 미상이며 관찰된 효과와 이번 구현 가설을 구별한다. 아래 판독은 원본 복제나 사용자 최종 품질 승인이 아니다.

## 사용자 교정과 이력

P1–P3의 전체 색·느낌·구획을 충분히 읽지 못하고 Q1–Q4 부분 adapted를 확대한 오판은 [review](review.md)에서 철회했다. `evidence/user-rejected-p3/`의 거절 앱·기준·증거를 보존한다. P4에서는 전체 개선에 대한 긍정적 피드백과 함께 카페별 구분 부족이라는 후속 지적을 받았다. 간격만으로 충분하다는 P4 RUI-25 판독은 해당 범위에서 철회한다. 커밋 `5b026fa`와 주요10파일이 일치하는 [감사 기록](evidence/p4-before-row-surfaces/baseline-audit.json)을 남겼다. 각 사용자 FAIL과 실제 CLI 이벤트는 [누적 기록](failure-events.jsonl)에서 구별한다.

P5는 교대 표면을 먼저 고정하고 조건 태그/아이콘, 닫힌 select 외형, 마감 날짜 보조행 제거를 순차 추가했다. 최초 입력에 모두 있었던 것처럼 기록하지 않는다. 태그 구현 후 사진 고정높이보다 조건이 길어진 문제도 별도 사용자 교정으로 보존하고 사진의 내용기반 높이를 맞췄다. 이후 사용자 명시요청으로 조건요약12px/가로시간을 추가했다. 중간 증거는 `evidence/p5-surfaces-before-tags/`, `evidence/p5-before-photo-fit/`에 보존한다.

## 최종 추가 교정과 재검증

12px 예외는 `.admission-tag`와 `.cafe-note`에만 적용한다. 태그14px에서 생긴 정보높이 증가와 사진관계를 먼저 배치로 교정한 뒤, 사용자의 추가 요청으로 전용 compact 토큰12px/16px를 도입했다. 320에서도 짧은 조건이 읽히며 200%에는24px/32px로 확대된다. 가격·시간·날짜·입력·CTA·동의·오류는14px이상, 같은 중요조건은 상세/예약조건/요약에14px이상으로 판단 전에 보존한다. 범위 밖으로 작은 글자를 확대하지 않는다.

`verify-times-p5.cjs`는 두 폭에서 6개 시간,72px이상 너비/44px이상 높이/14px 기본글자/다음칩일부노출, 숨긴 scrollbar 두 구현, 실제 가로휠과 CDP touch swipe, Tab으로 마지막시간 자동노출과 Enter선택을 확인했다. 가로이동량은390=122px/320=192px이며 목록의 마지막18시를 선택해 들어간 시트와 요약에서 이전으로 돌아온 시트 모두 끝선택을 노출한다. 확대시간은28px 한줄로 자연너비를 확보한다. 페이지 가로넘침은0이다. 날짜그리드는 가로시간 변경 대상이 아니다.

실제 키보드 캡처에서 목록 청색시간의 inset outline이 같은 청색이라 초점을 알아볼 수 없는 결함을 발견했다. `evidence/p5-time-focus-failure/`에 보존하고 부모에게 수정 요청했다. 최종 목록/선택시트의 청색버튼은 흰색 inset 초점, 미선택은청색, 고대비는 시스템색으로 구별된다. 두 폭의 실제 Tab·끝칩·시트선택·확대·고대비를 다시 실행하고 캡처를 직접 읽었다. 정상/고대비 초점 확인을 단순 DOM focus assertion으로 대체하지 않았다.

최종 첫 시간 영역 하단은 두 폭 모두732px로 nav시작780px 위다. 사진은 최소112px이며 정보행의 실제 높이를 채운다. 두 폭의 기본/필터/저장/확대/고대비에서 사진과정보의 박스높이·하단이 일치하고 crop은 공간/반려견 식별을 보존한다. 스크롤한3매장 전체를 직접 읽어 첫viewport만의 판독으로 대체하지 않았다.

## 게이트 범위

catalog v5 활성75개의 원래 checks를 유지하고 프로젝트10개를 추가한다. 미적용6개는 사이드바/다열대시보드/채팅이 없는 범위이며 수행하지 못한 검사를 미적용으로 바꾸지 않는다. 21개 예외는 모바일 상시시간/관례적 아이콘 전용 조작/참조 그림색/수직탭 간격 등 기존 구체 범위를 보존한다. P5 정보태그는 사용자 R3형 정보표현 요구에 한정하며 상태마다 임의색을 추가하는 근거가 아니다. 게이트 CLI는 증거 무결성을 검사하고 실제 시각 판독은 이 문서와 캡처에 별도로 남긴다.

실제 예약 API, 실제 매장 정책·가격, OS 팝업 방향키 경로, 실물폰/Safari, 사용자 최종 품질 승인은 검증 완료 범위에 포함하지 않는다.

최종 내부 게이트 대상은85개(활성75+프로젝트10)이며 판독 분류는 통과58/범위예외21/미적용6이다. 실제 CLI 결과는 [gate-result](gate-result.json)에 기록한다. 사용자 최종 품질 승인과 범위밖 OS 팝업 검증을 포함하는 완료 선언은 하지 않는다.

## P6 · 저장 활성/테마 hover의 새 판독

사용자는 저장 활성화가 보이지 않고 테마 hover가 불필요하다고 교정했다. `evidence/p6/before-active.png`를 직접 읽었다. 저장값/aria-pressed가 true여도 빈하트/먹색이었으므로 이전 데이터와 ARIA 검사를 실제 상태표현 검증으로 확대한 부분을 철회한다. 사용자 FAIL을 누적하며 이전 P5 PASS와 실패증거를 삭제하지 않는다.

`verify-p6-review.cjs`로390/320 각각 tap저장→청색채움+옅은면→activehover/해제유지→reload→저장탭상태→Space삭제→Enter추가→고대비채움/해제를 새로 실행했다. 실제 사진/버튼 박스는 동일하며 fill과배경이 상태를 구별한다. 고대비에서 검정채움/빈윤곽과키보드초점을 직접 판독했다. 저장상태를 색 하나에만 맡기거나 저장목록 결과만으로 대신하지 않는다.

테마는 hover진입/해제 모두 투명배경/transition0s/동일박스다. 키보드 Tab 초점은2px outline으로 식별되며 Enter 실내필터1개, 터치 마당필터2개를 확인했다. 테마표현 제거를 모든 버튼 hover/키보드초점 제거로 확대하지 않는다. 두폭의 actual PNG와 computed/행동은 `evidence/review-p6/`에 있다. 앱JS/새검증JS lint와checkJs는오류경고0이며토큰80개미정의/미사용0을재검산했다.

P6 변경없는 검색/태그/사진/가로시간/예약조건/완료·취소/텍스트확대 증거는 P5의 해당파일을 범위명시해 재사용한다. 이번 실행은 저장/테마와 목록 정보구조의 영향을 검증하는 targeted 후속이며 P5 전체행동을 다시실행했다고 쓰지 않는다. 최종 기준은 여전히85개(통과58/예외21/미적용6)이며 사용자품질승인과 기존 OS팝업/실예약/실물폰 한계를 확대하지 않는다.

## P6 추가 정보 교정의 최종 판독

첫 정보안의 실내/마당 상위태그와 별도 조건묶음은 사용자가 거절했다. 같은 동반조건을 잘못 분리한 제품해석이며 당시 구조검사PASS를 올바른 정보계층으로 확대한 판독을 철회한다. `evidence/p6-rejected-information/`에 소스/검사/중간캡처를 보존한다. 새로운 기준은 이름→14px의 짧은 카페소개→단일 ‘동반 조건’ group의 공간·크기·준비물 태그→예약시간이다. 모든 조건태그와 해당 caption만12px이고 확대시24px이다. 소개/핵심행동/상세·예약확인조건은14px이상을 유지한다.

`verify-p6-information.cjs`는390/320의 홈/전체지역/저장/필터/200%/고대비를 새로 실행하고 사진/정보의 동일높이·하단, 가로넘침0, 소개14px 및 조건12px하한을 측정했다. 성수처럼 제목이 지역을 한정한 홈에서는카드지역0개,전체지역에서는4개,성수·연남 저장에서는각지역이유지된다. 목록메뉴가격은없으며마당만동반은상세/예약요약의실내불가와같은가능범위를전달한다. 단독대관의크기무제한을추론하지않고단독이용/사전확인/미정대관비조건도보존한다. 후기나실제매장소개를검증했다는주장은없으며가상fixture체험범위를유지한다.

소개추가후320첫예약버튼하단6px가탭에가려지는문제를직접발견했다. `evidence/p6-first-time-clipping/`에보존하고목록날짜아래간격12→4의국소수정을요청했다. 최종재검증은390영역bottom732/버튼730,320영역bottom780/버튼778,탭top780으로가림없다. 최종정보캡처와Q4보드를직접읽어정보의미/줄바꿈/사진crop과첫진입을확인했다.

저장/테마캡처 `saved-*`, `forced-*`, `theme-*`는 정보변경 전 해당 상태 역할에 한정한 증거다. 현재 전체 정보화면은 `information-*`와P6최종보드를 사용한다. 새정보화면의저장목록에서도채운하트가유지됨을직접확인했다. 정보수정으로바뀌지않은예약입력/가로시간/완료·취소는P5검증범위만재사용하며전체새회귀로표현하지않는다. 검증결과는 [P6 평가](../../../evals/results/reference-controls-p6.md)에연결한다. 활성75+프로젝트10의85개기준은축소하지않는다.

## P7 현재 판독 · 목록 제목과 카드 간격

P6의 날짜 아래4px 결정은 사용자에게 위계가 불명확하다는 교정을 받았다. 이전 첫 viewport 수치와 PASS는 당시 기록이며 현재 간격 품질 승인이 아니다. app.css의 list-date 하단만20px로 변경했다. 제목↔날짜4px/날짜↔카드20px를390/320에서실측하고 실제 목록 및320확대를 직접 판독했다. 고정 탭 아래로 콘텐츠가 이어져도 스크롤/키보드로 첫·마지막 시간에 도달해 예약 dialog를 열 수 있다. 첫 viewport 안에 전체 버튼을 넣는 에이전트의 최적화보다 사용자가 지적한 의미 위계를 복원한다. 정상 스크롤을 실제 접근 불가 가림으로 판정하지 않는다.

P7은 간격1곳의 후속 검증이다. P6의 내용·상태·예약 흐름 및 변경없는 R1–R5 관계의 증거는 해당 범위에서 유지한다. 새 근거는 evidence/p7의 양폭/확대 이미지와 checks.json, P7 보드다. 전체 검사를 새로 수행했다고 하지 않는다. 이전 게이트7파일은 evidence/p6-before-spacing-p7에 보존한다.
